# Tracker 1.3.2 — cancelled-print accounting fix

Packages: **macOS Apple Silicon (arm64)** and **Windows x64**.

## Fixed

An observed print could enter an error state before the user cancelled it. Tracker
then failed to schedule partial accounting, or kept the intermediate error in
history even after the same job became cancelled. Its captured usage could remain
unaccounted.

Version 1.3.2 lets that verified error → cancellation transition use the existing
motion capture up to cancellation. It preserves the job's start snapshot and
advances the intermediate history state to cancelled. Existing checks still
verify tool mapping, spool continuity and agreement with the printer's extrusion
counter. Repeated or delayed history events do not apply another deduction.

The **1.3.1 display fix is retained**: after a matching print is accounted for,
head cards show current balances and its old slice forecast is cleared. This was
already published in 1.3.1; it is not a second new accounting change in 1.3.2.

## Limits

- Tracker must have observed and retained a valid capture for the same print.
  Missing data, mismatched counters or uncertain spool identity still require
  review. An upgrade does not automatically reconstruct earlier unaccounted jobs.
- Cancelled prints are not charged the full slicer plan or an elapsed-time ratio.
  Motion is commanded extrusion, not measured material: a tangled spool may slip.
- The strict counter-consistency tolerance is unchanged. This fix does not promise
  automatic accounting for every cancelled print.
- **Windows GUI and real Snorca slicing on Windows remain unverified.** Native
  CI tests and executable self-tests do not replace desktop testing.
- macOS packages use an ad-hoc signature and are not notarized. Real U1 printing
  with Spoolman and sustained operation retain the limitations of 1.3.0.
- Experimental Tracker 2.0 UID/RFID modules, multi-printer client and SQLite
  accounting are not included.

## Validation

Regression cases cover ordinary cancellation and error → cancellation, with and
without pause/resume; stale profiles; delayed motion and cancellation retraction;
intermediate history error/interruption; automatic replenishment on/off; repeated
accounting and delayed stale history. The suite also tests local mock U1 servers
and completed-print forecast behavior. No real printer is needed for these tests.

Desktop packages are built by GitHub Actions on native macOS and Windows runners.
Each package runs an executable self-test; macOS additionally checks its signature.
Attached BUILD-INFO files identify the exact commit and package SHA256. The release
preparation record records actual run results separately.

## Upgrade

Export a JSON backup and quit the old Tracker before replacing it. The inventory
directory, settings format and spool data format remain unchanged from 1.3.1.
Do not run both versions for the same printer. If Snorca's post-processing command
contains a versioned app filename, update it to 1.3.2.
See the [English guide](../guides/en.md) or [Russian guide](../guides/ru.md).

## По-русски

Исправлен случай, когда печать сначала переходит в ошибку, а затем отменяется.
Раньше Tracker мог не запустить учёт частичного расхода или оставить промежуточную
ошибку в истории. Теперь при сохранённой проверенной записи той же печати расход
до отмены может быть учтён. Повторные и запоздавшие события не списывают его дважды.

Сохранено исправление 1.3.1: после учёта печати показывается актуальный остаток,
а её старый прогноз исчезает. Оно уже было опубликовано в предыдущей версии.

При отсутствии записи, несовпадении счётчиков или неопределённой катушке требуется
проверка. Полный план отменённой печати не списывается. Старые неучтённые задания
после обновления автоматически не восстанавливаются. Движение экструдера — оценка,
а не измерение реально прошедшего филамента; при плохой намотке возможна пробуксовка.

Настройки и данные катушек сохраняются; перед обновлением экспортируйте JSON-backup
и закройте прежний Tracker. При необходимости обновите путь постобработки Snorca.
Windows GUI и настоящая нарезка на Windows остаются непроверенными. macOS — Apple
Silicon, ad-hoc подпись, без нотарификации. Эксперименты 2.0.0 в выпуск не входят.
