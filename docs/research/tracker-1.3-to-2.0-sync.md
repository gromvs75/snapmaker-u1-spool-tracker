## Интеграция с 2.0.0

Прочитан `docs/development/tracker-2.0.0-next-chat.md` основного рабочего каталога.
2.0 использует SQLite UID-каталог и многопринтерный учёт, а не прежнюю JSON-модель.
Последний записанный процессный Windows EXE стенд: `test/uid-windows-live`,
00339dd, Actions 42983972600. Перед интеграцией проверить актуальный HEAD другой
ветки: это ориентир, а не утверждение, что разработка там остановилась.

Не переносить старую базу/Store поверх UID-каталога. Перенести поведение API и
отображения через адаптер новой модели. Изменение подписи не меняет UID,
spool_id, привязку Spoolman, местоположение, ручное назначение, журнал расхода
или очередь отправки. Чтение сторонней метки само по себе не определяет остаток
и не доказывает безопасную границу замены катушки во время печати.

Перед объединением:
- Сверить исправления отменённых печатей и защиту от повторного списания.
- Прогнать тесты производителя, сравнения, stale revision, локальных катушек,
  недоступного каталога, ожидающего Spoolman outbox и переименования при печати.
- Проверить миграцию ручных/нетегированных катушек и Spoolman-привязок с backup;
  только один сервис может списывать расход.
- На двух процессных стендах проверить перенос UID, reconnect, повторы истории,
  ручную замену и отложенные списания Spoolman.
- Проверить одно поведение Windows и Mac: экран, трей, скрытие/открытие и выход.
- Сохранить отдельную отметку непроверенного GUI на машине пользователя;
  Windows Server CI не заменяет проверку Windows 10/11 и DPI пользователя.

Автодозаправка и ручная замена требуют отдельных достоверных данных U1.
Их исследовательские стенды не включены в rc4. Нет подключения к принтеру,
миграции установленной базы или публикации релиза в рамках этой сборки.
