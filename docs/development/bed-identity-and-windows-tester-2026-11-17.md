# Номера столов и разбор Windows-логов 1.3.3

17 ноября 2026. Интеграционная ветка `integrate/2.0-graphite-ui`.
Контрольная точка: `checkpoint/rc14-before-bed-identity`, `cbb42c0`.
Предыдущая полная регрессия: 907 passed, 3 skipped (rc14).

## Нумерация столов

Причина: `forecast_entry` интерпретировал суффикс `.PID.N.gcode` как номер
стола `N+1`. В Snorca v2.4.1 это `GLOBAL_PLATE_INDEX++`, общий счётчик временных
файлов; тот же счётчик используется для `*_config.3mf`. Это не `m_plate_index`.

Первичные источники:
- https://github.com/Snapmaker/OrcaSlicer/blob/v2.4.1/src/slic3r/GUI/PartPlate.cpp
  (`get_tmp_gcode_path`, `get_temp_config_3mf_path`, `store_to_3mf_structure`).
- https://github.com/Snapmaker/OrcaSlicer/blob/v2.4.1/src/libslic3r/Format/bbs_3mf.cpp
  (`model_settings.config`, `plater_id`, `gcode_file`, `has_restore_data`).

2.0 теперь читает явное соответствие `plater_id` → `gcode_file` из
`Metadata/model_settings.config` либо этого XML внутри локального `.3mf` /
`*_config.3mf` в том же проекте. Число уже начинается с 1, повторного +1 нет.
Номер из имени файла и перечисление найденных файлов не используются.

Файл должен быть явно указан в метаданных; другой проект, старый снимок
(метаданные старше завершённого G-code), неоднозначные/повреждённые данные,
символические ссылки и превышение лимитов не дают номер. Архив не распаковывается
на диск, читается только ограниченный XML. XML DTD/entities не принимаются.
Если подтверждения нет: «Стол не определён» и имя файла для различения нарезок.
Это не ошибка нарезки и не повод отменять просмотр расхода.

Русский пользовательский интерфейс и трей используют «Стол». Сохранены
переводы Plate / Platte / Стіл / Placa. Номер относится к сохранённым метаданным,
а не доказывает, что именно этот стол сейчас выбран в интерфейсе Snorca.

Ограничение: Snorca не обязан обновлять метаданные вместе с каждым временным
G-code. Поэтому при отсутствии свежей явной связи возможен неизвестный номер.
Не обещаем восстановление 1/2 по одному только набору файлов .PID.2/.PID.3.

## Переданные архивы тестировщика

Оба RAR прочитаны и распакованы только в игнорируемую `output/tester-133-review/`.
Исходные архивы не изменены. Их содержимое не импортировалось в приложение,
адреса из настроек не использовались. Оригинальные логи и базы не коммитятся.

В обоих снимках есть задание `000180`, `Adventskalender Magnethalter _PLA_9m11s.gcode`.
Сохранённый план: `[0, 1.55, 0, 0]` г — расход логического материала №2.
Сохранённая карта: `[0, 3, 2, 3]`; физический расход `[0, 0, 0, 1.55]` г.
Это соответствует четвёртой головке T3 на скриншоте. T1 в прогнозе — отдельная
ошибка предположения «логический материал i → физическая головка i-1».

Хронология (время из журнала тестировщика):
- 16.11 16:51:00,763: Print start: OK.
- 16.11 16:51:04,007: Printer job 000180: active.
- 16.11 16:57:31,950: Cannot verify U1 mapping for accounting: <urlopen error timed out>.
- 16.11 16:57:31,962: Printer job 000180: review.
- В снимке после печати: `terminal_status=completed`, `status=review`, причина
  `U1 tool mapping is unavailable or incomplete`.

Катушки и назначения в двух JSON-снимках совпадают: этот сценарий не изменил
остатки. Пропуск вызван тайм-аутом во время активной печати, не выключением ПК
и не неверной картой при старте. В 1.x отсутствие проверенной карты переводит
active → review; последующая история completed сама review не разрешает.
Почему именно HTTP-запрос не успел ответить (сеть, нагрузка, сервер), архивы
не доказывают. Увеличение тайм-аута не выдаётся за устранение причины.

## Сравнение с 2.0

| Сценарий | Результат сравнения |
|---|---|
| Материал №2 в прогнозе показан на T1, хотя перед отправкой выбран T3 | Предположение есть и в 2.0. **Открыто**: нужна отдельная явная карта для предпросмотра либо достоверные данные слайсера. Нельзя брать карту прошлого задания, угадывать по цвету или числу прутков. Прогноз не используется как разрешение на списание. |
| Теряется непрерывность при HTTP timeout | 2.0 тоже прекращает считать наблюдение непрерывным; это необходимая защита. Есть сохранённый план, история и отдельный путь расчётного восстановления. |
| Неиспользуемый материал дублирует T3 в карте `[0,3,2,3]` | Найден и исправлен дефект `Recovery.preview`: карта больше не обязана быть перестановкой всех четырёх головок. Проверяется корректность значений и отсутствие совпадения головок у **используемых** материалов. |
| Повтор completed после восстановления | На искусственном сценарии 1,55 г относятся к T3 один раз, после повторов и пересоздания lifecycle дополнительных проводок нет. |
| Конечная карта неизвестна | Автосписание запрещено; сохранённый план доступен для проверки. Старые данные не подставляются вместо текущего свидетельства. |

Исправление preview не ослабляет проверки UID, истории, смены катушки,
неопределённых отправок Spoolman и частичного учёта. Общая головка для нескольких
используемых материалов по-прежнему требует отдельного разбора распределения.
RFID, полноценный ручной режим и исследование автодозаправки в этом этапе
не дорабатывались. Правила автодозаправки и допуски motion не менялись.
