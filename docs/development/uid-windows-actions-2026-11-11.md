## Найденная и исправленная ошибка

Первый Windows запуск: 126 тестов прошли, 3 упали. Миграция успешно записывала
файл, но затем вызывала `os.open(directory)` для POSIX fsync каталога. Windows
возвращала PermissionError, и миграция ручных катушек останавливалась.

В `src/tracker_uid_migration.py` добавлен отдельный Windows путь: содержимое
временного файла flush/fsync, затем MoveFileExW с REPLACE_EXISTING и WRITE_THROUGH.
Ошибки Windows API передаются вызывающему коду; POSIX ветка сохранена.
Поведение API: [документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).
Проверка не моделирует внезапное отключение питания или отказ накопителя.

После исправления на Windows прошли 144 теста, включая полную миграцию,
backup/restore, ручные назначения, перенос, истечение и идемпотентность,
постоянную защиту прерванного задания, сборщики и повторную историю через очередь
после reconnect/перезапуска SQLite. На macOS отдельно прошли 129 исходных
регрессионных тестов и 15 тестов миграции после исправления.

## Нативная проверка

Сценарий `dev/labs/uid_windows_bench/run.py` открывает настоящее окно WebView2.
Клики и drag идут через Win32 mouse events, DOM используется для проверки
результатов. Снимки — захват рабочего стола Windows через Pillow.
Первый проход нативного окна выявил ограничение стенда: экран 1024×768 обрезал
кнопки большого окна. Стенд теперь задаёт отдельный рабочий стол 1920×1080
и фиксированное положение окна; это изменение тестовой инфраструктуры.

## Границы заключения

Windows Server runner не заменяет проверку установленной сборки на пользовательских
Windows 10/11, разных DPI/нескольких мониторах. Проверки сборщиков используют
синтетические сокеты/историю. Два настоящих Klipper/Moonraker процесса на Windows
в этом workflow не запускаются; прежний процессный стенд описан отдельно.
