# Tracker 1.3.0 — Spoolman integration

**Prepared release; not published.** No release tag or installation is part of this preparation.

Spool tracking and usage forecasts for Snapmaker U1 — **without firmware changes**.
Spoolman connects through Tracker; no components need to be installed on the printer.

## Changes

- Optional Spoolman **0.27.1** catalog and balance reading, with physical spool assignments to T0–T3. Local-only inventory remains available.
- Read-only mode sends no consumption. Slicing displays a forecast and never deducts filament.
- Explicit usage-delivery mode for registered, matched, successfully completed prints, with sole-sender confirmation. Usage for external spools is recorded in Spoolman without a second local deduction.
- Durable delivery queue and duplicate-event protection. A lost write response is marked uncertain and blocks automatic delivery until reviewed; no exactly-once guarantee is claimed for ambiguous requests.
- Backup restoration disables the Spoolman integration and marks unfinished deliveries uncertain. Old prints are not automatically resent when enabling delivery.
- Verified logical-to-physical mapping at print start; missing or changed mapping requires review. Pre-slice forecasts still visibly assume material 1→T0 … 4→T3.
- Clearer printer connection testing/status, independent of enabling automatic accounting.
- macOS fixes retain the menu bar and bring the requested dashboard to the front. After slicing, the menu opens without opening the main window; no Dock icon.
- RU/EN integration guides, stock-firmware wording and Spoolman MIT attribution included in both distributions.

## Validation and limitations

The preceding previews were tested with a local Spoolman 0.27.1 instance, artificial spools and a U1 simulator: read-only forecasts and shortage, successful accounting, repeated events/restart, server outage, multi-color partial delivery, lost response, mode changes, backup restoration and all 24 permutations of T0–T3. Native macOS preview checks covered mode switches, backup actions and menu/window behavior. Release-specific CI results and exact source hashes are recorded alongside the prepared archives.

**Windows GUI and real Snorca slicing on Windows remain unverified.** CI tests and packaged `--self-test` are not desktop validation. Real U1 printing with Spoolman and sustained operation still require user validation. No real printer or inventory was used for these integration tests.

Balances and consumption are estimates from registered slice data, not scale measurements. Four logical materials are supported; this is not full 32-material mapping support. The supported Spoolman version is 0.27.1. Catalog freshness is limited to 60 seconds; stale/unknown data cannot produce a positive forecast. Reverse-proxy authentication and redirects are not supported. New Spoolman settings are RU/EN, with English fallback for other languages.

macOS package targets Apple Silicon, is ad-hoc signed and is not notarized. Windows targets x64.

## Upgrade and first connection

1. Before a future upgrade, export a JSON backup from the installed Tracker. Close other instances that account for the same printer.
2. 1.3.0 uses the existing `SnapmakerSpoolTracker-Beta12` data directory and port 8766, as 1.2.1 did. Preview inventories are not imported automatically. This release preparation does not install or open the release against that directory.
3. Spoolman is a separate server. Begin with catalog reading only and keep usage delivery off. For an isolated first check, keep the printer monitor off too.
4. Follow the [Russian guide](../guides/spoolman-ru.md) or [English guide](../guides/spoolman-en.md) before enabling usage delivery. Tracker backup does not restore or roll back Spoolman balances.
