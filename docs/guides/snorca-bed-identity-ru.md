# Номер стола Snorca в Tracker 2.0

Поддерживается начиная с кандидата 2.0.0rc16. Проверено на движке Snapmaker
Orca 2.4.1 для macOS. Windows-сборка этого изменения пока не проверена.

**Для надёжного отображения «Стол 1», «Стол 2» необходима однократная
настройка каждого используемого профиля принтера Snorca и новая нарезка.**
Tracker не добавляет эту настройку автоматически. Без неё прогноз расхода
может работать, но определение номера стола не гарантируется.

## Настройка в Snorca

Snorca знает номер стола при нарезке, но не всегда сохраняет связь номера с
временным G-code в резервном проекте. Для надёжной передачи номера используйте
в профиле принтера Snorca одну дополнительную строку **комментария** в начале
поля `Machine start G-code` (G-code начала печати):

```gcode
; TRACKER_BED_V1 = {plate_number}
```

Сохраните профиль как отдельный пользовательский профиль. Весь существующий
G-code начала печати оставьте после этой строки. Не заменяйте переменную числом
и не убирайте точку с запятой: это комментарий, а не команда принтеру.
В настройках прошивки ничего менять не требуется.

1. Откройте настройки выбранного **принтера** Snorca → **«G-код принтера»**.
2. В поле **G-code начала печати / Machine start G-code** вставьте указанную
   строку первой, перед существующим кодом (например, перед строкой с датой).
   Это не поле скриптов постобработки в настройках процесса.
3. Нажмите **дискету** и сохраните отдельный профиль, например
   **«Snapmaker U1 · Tracker»**.
4. В основном окне проекта **выберите сохранённый профиль принтера**.
   Самого редактирования поля недостаточно, если нарезка использует другой профиль.
5. Снова откройте его G-code начала печати и убедитесь, что строка сохранилась
   ровно один раз, с точкой с запятой и `{plate_number}` вместо конкретного числа.
6. Заново нарежьте нужные столы с выбранным профилем.

Экспорт или отправка на принтер для обновления прогноза не нужны. Snorca подставляет `01`, `02`, `03` и т.д.
в каждый файл уже при нарезке. Tracker показывает «Стол 1», «Стол 2»,
«Стол 3». Отдельно нарезанный стол 3 остаётся столом 3.

## Проверка и устранение «Стол не определён»

После завершения нарезки в Tracker **2.0.0rc16 или новее** откройте
**«Обзор → Прогноз нарезки»**. Номер должен совпадать со столом в Snorca.
Для проверки нарежьте отдельно стол 2: он должен остаться «Стол 2».

Если номер не определён:

- Проверьте выбранный **в текущем проекте** профиль принтера и сохранённую строку.
  Открытие другого 3MF, переключение профиля или сброс настроек могут вернуть
  профиль без комментария. Повторите проверку перед новой нарезкой.
- Убедитесь, что нарезка выполнена заново после сохранения и выбора профиля,
  а в Tracker показаны источник и время именно этой нарезки.
- При необходимости экспортируйте G-code только для диагностики и найдите
  отдельную строку вида `; TRACKER_BED_V1 = 02` в начале исполняемого блока.
  Строка `machine_start_gcode` с текстом `{plate_number}` в сохранённых параметрах
  файла сама по себе не подтверждает передачу номера.
- Если подставленной строки нет — она не попала в настройки этой нарезки.
  Если строк несколько, в ней осталось `{plate_number}` или указан неверный
  формат — проверьте профиль и повторите нарезку. Не исправляйте номер вручную
  в готовом G-code.
- Если корректная строка есть, но номер всё равно неизвестен, сохраните G-code,
  версию Tracker и сведения об источнике прогноза для диагностики.

Подключение принтера, подтверждение назначения катушки и ручное списание
для определения стола не требуются. Этот комментарий не заменяет отдельную
настройку учёта расхода, Spoolman или RFID.

## Подготовленная копия проекта и ограничения

В рабочие настройки пользователя эта строка автоматически не устанавливается.
Разработчик может подготовить отдельную копию 3MF командой:

```sh
python dev/prepare_bed_marker_project.py input.3mf output-with-bed-marker.3mf
```

Копия сохраняет модели и остальные настройки; изменяется только добавление
комментария в `Metadata/project_settings.config`. Откройте её как проект с его
настройками и заново нарежьте. При переключении на другой профиль принтера
проверьте наличие строки: профиль без неё не передаёт номер.

Номер означает стол **на момент данной нарезки**, а не текущий выбор в окне
Snorca. После перестановки столов нужна новая нарезка. Старые G-code не получают
номер задним числом. Без маркера Tracker продолжает читать явные свежие ссылки
проекта; при отсутствии связи показывает «Стол не определён».

Маркер не определяет физическую головку, не подтверждает UID и не разрешает
списание. Прогноз материалов до отправки и учёт расхода остаются отдельными
механизмами. Некорректные или повторяющиеся маркеры не используются.

Основание: в [Print.cpp Snorca 2.4.1](https://github.com/Snapmaker/OrcaSlicer/blob/v2.4.1/src/libslic3r/Print.cpp)
`get_plate_number_formatted()` возвращает `get_plate_index() + 1` с ведущим
нулём; [GCode.cpp](https://github.com/Snapmaker/OrcaSlicer/blob/v2.4.1/src/libslic3r/GCode.cpp)
передаёт это значение переменной `plate_number` перед обработкой стартового G-code.
