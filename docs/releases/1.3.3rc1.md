# 1.3.3rc1 — startup lock handling test build

Based on 1.3.2, including its cancelled-print accounting fix.

A busy Spoolman worker lock now produces a clear message and exits before creating the dashboard or starting printer monitoring. The existing lock is preserved; no second synchronization worker is allowed.

Windows GUI and real Snorca slicing on Windows remain **UNVERIFIED**. CI tests and packaged self-test do not replace manual desktop testing.

## Проверка на Windows

1. Экспортируйте резервную копию в установленном Tracker и закройте его через меню в трее.
2. Запустите тестовую сборку. Проверьте окно, версию и сохранённые катушки/настройки.
3. Запустите её повторно: должно открыться существующее окно либо появиться понятное сообщение, без traceback.
4. Закройте Tracker через меню в трее и запустите снова: запуск должен пройти нормально.
5. Если блокировка остаётся, перезагрузите Windows и повторите запуск один раз. Сообщите, повторилась ли ошибка, и приложите её текст.

Не удаляйте базу данных или файл блокировки. Не запускайте одновременно разные версии для учёта одного принтера.
