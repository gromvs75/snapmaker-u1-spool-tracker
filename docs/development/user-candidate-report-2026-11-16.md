## Найденные проблемы и границы выводов

1. Каталог Spoolman в лабораторном bridge игнорировал allowlist. Теперь проверка
   применяется до создания HTTP-клиента; redirects по-прежнему запрещены.
2. В первом процессном прогоне один старт получил
   `Unique active history identity unavailable`, хотя motion-соединение продолжалось.
   История прочитана до старта, статус — после. Добавлено одно повторное чтение
   истории/статуса с проверкой неизменности и единственности задания. Если оно
   остаётся неоднозначным или есть ошибка транспорта, запрет сохраняется.
   Это подтверждённый стендовый механизм пропуска **при работающем компьютере**,
   а не доказанная причина всех ранее сообщённых реальных пропусков.
3. Обычный Python signal handler мог не выполниться внутри Cocoa run loop.
   На macOS используется PyObjCTools.MachSignals. Повторный packaged-прогон
   завершился корректно, в том числе при работающих сборщиках.
4. Прежняя ForecastService передавала готовые события, но не состояния
   повторной нарезки/удаления. Новый прогноз берёт текущие состояния observer.
   Это исправляет показ старых количеств во время изменения файла. Причина всех
   реальных задержек обновления до отправки остаётся отдельным исследованием.
5. Ручное подтверждение не исправляет сбор наблюдений. Оно записывает отдельное
   решение и дополнительные дебеты. После замены поля не заполняются всем планом
   старой катушки. Неопределённая отправка этого задания блокирует новое ручное
   списание до сверки; уже локально списанное включено в показанную сумму.
6. При активном подключении ручное окончательное решение требует свежего idle/
   complete/cancelled/error статуса и того же поколения соединения. Без связи
   требуется явное подтверждение пользователя о завершении; данные не выводятся
   из наличия питания компьютера или состояния слайсера.
