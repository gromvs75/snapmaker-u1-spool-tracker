Пользователь явно согласовал безопасные изменения текста: нет обещания отмены

предлагают прочитать состояние, открыть сверку уже учтённого расхода либо
разрешения новой попытки. Кнопка «Открыть» не отправляет расход и не сохраняет
решение. Подтверждение не выставляется автоматически. Требуются основание,
ручное подтверждение, затем отдельная явная отправка выбранной операции.
«Пропустить» скрывает лишь предложение до обновления, операция остаётся видна.

Браузерные проверки на синтетическом состоянии: applied/not_applied правильно
выбираются, сохранение без основания/галочки disabled, при открытии формы
выполняется только чтение audit. Backend revision/idempotency/quarantine не менялся.

## Исправления Windows

- Ожидаемый отказ второму процессу теперь превращается в контролируемый exit 2.
  Ранее необработанная ошибка в windowed PyInstaller открывала блокирующий
  bootloader dialog. Блокировка SQLite при этом работала правильно.
- Размер нативного окна ограничен рабочей областью Windows: исходные 1202×950
  обрезались на рабочем столе runner 1024×768.
- Исправлен внешний UI-тест: точное имя значка трея вместо совпадения части имени
  с кнопкой открытого приложения на taskbar. Команды приложения напрямую не
  вызываются: тест кликает настоящее меню «Открыть Tracker» и «Выход».

## Ограничения

Это изолированная стендовая сборка с явным каталогом данных и allowlist адресов,
не выпуск для замены установленного Tracker. Автодозаправка T3→T1 остаётся
отдельным нерешённым исследованием; её автоматическое списание не разблокировано.
