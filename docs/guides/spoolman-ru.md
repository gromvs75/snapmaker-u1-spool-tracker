# Spoolman — Tracker 1.3.3

Tracker 1.3.3 с интеграцией Spoolman. Перед обновлением экспортируйте JSON-backup из установленного Tracker.
U1 продолжает работать на оригинальной прошивке. Snorca менять не нужно.
Spoolman устанавливается отдельно; проверена версия **0.27.1**.

## Данные и запуск

- Приложение: `SnapmakerSpoolTracker-1.3.3.app` (macOS Apple Silicon).
- Данные: прежняя папка 1.2 beta / 1.2.1 `SnapmakerSpoolTracker-Beta12` в стандартном
  Application Support / LocalAppData. Порт локального интерфейса: 8766.
- Существующие данные 1.2 beta / 1.2.1 сохраняются. Данные Spoolman Preview не импортируются автоматически.
- Монитор принтера по умолчанию выключен. Не включайте его одновременно с
  другим Tracker, ведущим учёт того же U1.
- Сборка ad-hoc подписана, не нотариализована. Windows GUI и реальная нарезка
  Snorca на Windows остаются непроверенными.

## Соединение с U1 и импорт JSON

При чистой установке монитор принтера выключен. Статус «Автоматический учёт выключен»
не означает ошибку сети или IP. Результат разовой проверки соединения показан отдельно.
Ввод адреса не включает фоновый монитор. Настройки сохраняются отдельной кнопкой;
«Проверить соединение» выполняет разовую проверку и не включает автоматический учёт.

Импорт JSON-backup восстанавливает **не только катушки**, но и адрес/порт U1,
назначения, историю и настройку «Включить автоматический учёт».
Если эта настройка была включена в backup, монитор может подключиться после импорта.
Импорт не является обязательным способом подключения принтера.
Перед импортом следует остановить другие экземпляры Tracker, ведущие учёт этого U1,
и учитывать, что импорт может включить учёт в Tracker. После импорта проверьте
настройки монитора. Строгая защита при импорте сбрасывается в режим предупреждения.

Для первой проверки Spoolman достаточно чтения каталога: соединение с U1 и
автоматический учёт не требуются. Включите «Читать каталог и остатки», оставьте
«Передавать расход печати» выключенным. Монитор U1 также оставьте выключенным:
режим чтения Spoolman не отключает существующий учёт локальных катушек Tracker.
Восстановление backup отдельно отключает интеграцию Spoolman; подключать её нужно заново.

## Поведение окна macOS

После нарезки показываются значок результата и раскрывающееся меню; основное окно
автоматически не открывается. Оно вызывается через «Настроить катушки и слоты…».
Исправления строки меню и выхода окна на передний план из Preview 5 сохранены.

## Кто за что отвечает

- Snorca рассчитывает расход при нарезке. Прогноз не является измерением веса.
- Tracker сопоставляет файл, назначения катушек и события печати U1 на **оригинальной прошивке**.
- Spoolman хранит каталог конкретных катушек и их остатки. Для внешней катушки именно
  Spoolman является источником остатка; Tracker показывает его локальную копию.
- Метки RFID и кастомная прошивка для этой интеграции не нужны. Назначение катушек
  Spoolman в T0–T3 выполняется явно. Материал и цвет не идентифицируют физическую катушку.

## Установка Spoolman отдельно от Tracker

Поддерживается **0.27.1**, не произвольная версия `latest`. Официальное руководство:
https://github.com/Donkie/Spoolman/wiki/Installation

На Mac штатный переносимый способ — Docker. Docker должен быть установлен и запущен
по инструкции его поставщика. Пример для отдельного нового сервера на этом же Mac:

```yaml
services:
  spoolman:
    image: ghcr.io/donkie/spoolman:0.27.1
    restart: unless-stopped
    ports:
      - "127.0.0.1:7912:8000"
    volumes:
      - spoolman-data:/home/app/.local/share/spoolman
    environment:
      TZ: Europe/Berlin
volumes:
  spoolman-data:
```

Сохраните в новой папке как `compose.yaml`, выполните из неё `docker compose up -d`.
Откройте `http://127.0.0.1:7912`. Для остановки без удаления данных:
`docker compose stop`; для запуска: `docker compose start`. Не удаляйте том
`spoolman-data`: в нём база. Этот пример Docker приведён по документации upstream;
в текущем Mac-стенде проверен сервер из исходников 0.27.1, а не Docker-развёртывание.

Если порт 7912 занят уже работающим тестовым Spoolman, не запускайте второй на том
же порту: используйте другой свободный порт и укажите его в Tracker. Для сервера
на NAS/другом компьютере нужен его LAN-адрес; `127.0.0.1` всегда означает текущий Mac.
Spoolman не имеет встроенной авторизации; не открывайте этот порт в Интернет.
Пример выше доступен только локально. Сервер и Mac должны работать во время учёта;
Mac не должен спать. Сопоставление заданий, начавшихся пока Tracker не работал,
может потребовать ручной сверки, а не автоматического списания.

Для проверки с искусственными катушками используйте отдельную учётную запись ОС
и отдельный тестовый сервер Spoolman. Обычный запуск 1.3.3 использует прежнюю базу
Tracker: название архива не делает её тестовой. Режим `--isolated-root` предназначен
для автономных тестов и не разрешает подключение к Spoolman.

## Создание каталога и первая безопасная проверка

1. В Spoolman создайте материал/филамент, затем отдельную **катушку** этого филамента.
   Один материал может иметь несколько физических катушек с разными ID и остатками.
2. Укажите фактическую массу пластика. Вес пустой катушки — отдельная величина;
   его нельзя прибавлять к остатку пластика. Для теста создайте `TEST PLA`, 1000 г.
3. Проверьте запись в разделе катушек Spoolman: ID, материал, цвет и остаток.
   Одной записи в библиотеке филаментов для назначения в Tracker недостаточно.
4. Для теста откройте Tracker в отдельной учётной записи ОС с пустой базой.
   Не импортируйте реальный backup. В «Настройки» оставьте монитор U1 выключенным.
5. Подключите каталог только для чтения, как описано ниже. В назначении катушек
   выберите именно `TEST` и нужную головку. Не меняйте реальные назначения ради теста.
6. Нарежьте модель в Snorca без отправки на принтер. Сверьте расход, остаток и запас.
   Запас влияет на результат «хватает», но не списывается и не вычитается из прогноза
   «после печати». Для проверки нехватки назначьте отдельную малую тестовую катушку.

## Подключение

В «Настройки → Spoolman» введите базовый адрес своего сервера, например
`http://192.168.1.10:7912`, без `/api/v1`, логина и пароля в URL.

Включите «Читать каталог и остатки». Для списания также включите «Передавать расход печати» и подтвердите единственного отправителя. Нажмите «Сохранить настройки». Верхняя строка показывает сохранённый режим, а не несохранённое положение переключателей.

Режимы работы:

- **Только чтение**: каталог и остатки используются в прогнозе; Tracker не
  передаёт расход внешних катушек. Если никакая другая интеграция не обновляет
  Spoolman, остатки сами уменьшаться не будут.
- **Tracker отправляет расход**: подтвердите, что только этот экземпляр Tracker
  отправляет расход этого U1. Учёт должен быть также включён в настройках
  монитора принтера. Повторные события истории не создают новых списаний.

Нажмите «Сохранить настройки», выберите катушку и T0–T3, нажмите «Назначить».
Подключённые катушки имеют префикс `[Spoolman #ID]`. Локальные катушки сохраняются.
Одну физическую катушку нельзя назначить двум головкам. Цвет/материал на экране
принтера не заменяют идентификатор конкретной катушки Spoolman.

Прогноз после нарезки работает через существующее наблюдение Snorca. Перед
показом нового результата Tracker обновляет внешний каталог. Нарезка, повторная
нарезка и просмотр меню ничего не списывают. Отсутствие свежих данных, неизвестный
остаток, архивная/удалённая катушка или неразрешённая отправка дают неопределённый
результат вместо зелёного подтверждения. Возраст кэша ограничен 60 секундами.

## Учёт и сбои

Применяются прежние правила учёта печати, включая условия для оценочного расхода
и ручной сверки. Интеграция не повышает точность измерения. Для внешней катушки
локальный баланс — только кэш Spoolman. Списание заменено постановкой операции
в устойчивую очередь в той же транзакции, где фиксируется учёт печати.

- «Ожидает отправки»: операция ещё не отправлена; недоступность сервера оставляет её в очереди.
- «Подтверждено»: Spoolman успешно ответил на списание.
- «Результат неизвестен»: отправка могла выполниться. Автоматический повтор и
  дальнейшая отправка очереди остановлены.
- «Только чтение»: Tracker сохранил факт учёта, но не отправлял расход. Включение
  отправки позднее не списывает такие старые записи.

Для неизвестного результата сначала выясните, применилось ли списание.
«Уже учтено» закрывает операцию без записи. «Не учтено: отправить» разрешает
повтор **только после подтверждённой проверки**, с обязательной заметкой.
«Закрыть без отправки» сохраняет решение в журнале. Изменение остатка само по
себе не доказывает результат операции — его мог изменить другой принтер.

## Отключение и backup

Неотправленные/неоднозначные операции нужно разрешить перед отключением,
сменой сервера, отвязкой катушки и импортом backup. Отвязка удаляет только
локальную ссылку и назначения; данные Spoolman не удаляются. Для перехода
к автономному учёту создайте локальную катушку с проверенным остатком.

При восстановлении backup отправка выключается, незавершённые операции становятся
неоднозначными. Можно заново подключить **тот же** сервер, затем сверить операции.
Автоматического воспроизведения старой очереди нет. Не переносите одну отправляющую
базу на два компьютера для параллельного учёта одного U1: локальная блокировка
предотвращает два отправителя из одной папки, но не координирует разные компьютеры.

## Ограничения

- Новый экран пока переведён на русский и английский; в остальных языках его
  новые тексты отображаются на английском. Существующие переводы сохранены.
- Только Spoolman 0.27.1. Каталог до 10000 катушек; чтение постраничное.
- HTTPS использует обычную проверку сертификата; самоподписанные сертификаты,
  redirect и серверы за авторизацией reverse proxy в версии 1.3.3 не поддержаны.
- Надёжная связь «ровно одно списание» при потере ответа невозможна без сверки:
  upstream `/use` не поддерживает дедупликацию по ID операции.
- Реальный U1 и установленный Tracker при разработке не использовались.
  Длительная реальная печать остаётся этапом пользовательской проверки.
- Проверку остатка по весам v1.4 в эту работу не включали.

[Spoolman](https://github.com/Donkie/Spoolman) — независимый проект Daniel Hultgren
под MIT. Tracker использует его API; исходники Spoolman не включены в приложение.


## Включение списаний: порядок действий

1. Сделайте резервные копии **обоих** приложений. Завершите активные печати.
2. Проверьте назначения Spoolman ID → T0–T3 и актуальность остатков.
3. Убедитесь, что никакой другой Tracker или интеграция не отправляет расход этого U1.
4. В настройках Spoolman включите «Передавать расход печати», подтвердите единственного
   отправителя и сохраните. Режим в верхней строке должен измениться.
5. Для реального использования отдельно задайте адрес U1 и порт (обычно 7125),
   проверьте соединение, включите автоматический учёт и сохраните настройки принтера.
   Бекап для этого не требуется. В тестах используйте только адрес локального симулятора.
6. Для автоматического учёта нужен зарегистрированный план расхода и надёжное
   сопоставление файла/головок в существующем процессе Tracker. Один прогноз из
   наблюдаемой папки Snorca не заменяет регистрацию задания. Настройка hook и
   сопоставление файла описаны в [основном руководстве](ru.md).
7. После успешной сопоставленной печати проверьте историю и раздел передачи расхода:
   операция должна стать подтверждённой; Spoolman — показать уменьшение остатка.
   Нарезка, экспорт и загрузка файла не являются завершённой печатью.
8. Переключение из чтения в списание не отправляет старые записи, созданные при чтении.
   Не компенсируйте их автоматически массовым повтором: сначала сверяйте фактический расход.

## Что делать при обрыве связи

| Состояние | Действие |
|---|---|
| Ожидает отправки | Восстановите сервер/сеть. Не списывайте те же граммы вручную параллельно. |
| Подтверждено | Ничего не повторяйте: расход уже принят. |
| Результат неизвестен | Сверьте конкретную катушку и расход в Spoolman; очередь остановлена. |
| Только чтение | Запись не отправлялась; позднее включение списаний её не отправит. |

При неизвестном результате введите заметку с основанием сверки и выберите:
«Уже учтено» — не отправлять снова; «Не учтено: отправить» — разрешить повтор;
«Закрыть без отправки» — зафиксировать решение без списания. Если установить факт
невозможно, оставьте операцию неопределённой. Не выбирайте «Не учтено» наугад.
При многоцветной печати операция создаётся на каждую катушку: часть уже может быть
подтверждена. Сверять нужно каждую, а не повторять весь расход задания.

## Резервные копии: два независимых набора данных

**Tracker:** в нативном окне приложения → «Настройки» → «Экспорт копии». Сохраняйте
JSON вне папки приложения. В обычном браузере кнопки экспорта/импорта недоступны.
Для восстановления выберите «Импорт копии», нужный JSON и подтвердите замену
текущих данных. Перед заменой Tracker создаёт локальную защитную копию.

**Spoolman:** сохраняйте его базу отдельно по
https://github.com/Donkie/Spoolman/wiki/Backup-and-Restore . JSON Tracker не содержит
базу Spoolman и не откатывает его остатки. Для SQLite копирование остановленной
базы/тома исключает незавершённую запись; следуйте процедуре своей установки.

После импорта Tracker интеграция Spoolman выключена; незавершённые отправки из
backup становятся неопределёнными. Восстановленный адрес и включённый монитор
принтера могут активировать соединение: для тестов импортируйте только тестовый JSON.
Подключите тот же сервер Spoolman, проверьте назначения, сверяйте неопределённые
операции и лишь затем продолжайте учёт. Уже списанные операции не повторяются.
Восстановление более старой копии **Spoolman** отдельно может вернуть старые остатки;
это требует общей сверки, а не повторного отправления истории Tracker.

## Частые вопросы

- **Нет катушек в списке:** проверьте адрес, версию 0.27.1, режим чтения и кнопку
  обновления; в Spoolman должна существовать катушка, не только филамент.
- **Сохранение режима отклонено:** закончите печать и разрешите незавершённую очередь.
  Для полного отключения сначала отвяжите внешние катушки. Их записи в Spoolman останутся.
- **Прогноз неизвестен:** обновите каталог, проверьте доступность, остаток и очередь.
  Неизвестный результат нельзя считать подтверждением достатка материала.
- **Остаток не уменьшается:** проверьте режим отправки, монитор, сопоставление задания
  и очередь. Чтение каталога само по себе не включает учёт.
- **Два компьютера:** не включайте отправку одного U1 в двух независимых базах Tracker.

## Границы проверки

Списание и сбои проверены на настоящем Spoolman 0.27.1 с искусственными катушками
и HTTP-симулятором U1. Проверены повторные события, повторный запуск компонентов,
разрыв соединения и потеря ответа, многоцветный расход, переключение режимов и backup.
Это не проверка длительной физической печати. На Windows пользователь проверил запуск, выход, поиск, назначения катушек и сохранение настроек в rc5. Другие конфигурации требуют отдельной проверки.

## Катушки и названия в 1.3.3

В «Настройки → Spoolman → Катушки» поиск работает по названию, производителю, материалу и ID. Выберите катушку, головку и нажмите «Назначить». Отвязка не удаляет запись из Spoolman. Остатки внешних катушек редактируются в Spoolman.

«Проверить названия» сравнивает уже связанные записи. Выберите отличающиеся названия и примените обновление в Tracker; остатки, история и назначения сохраняются. Если названия совпадают, обновление не нужно. Это не объединение отдельно созданных локальных катушек с записями Spoolman.

Автодозаправка и ручная замена в процессе печати пока не гарантируют автоматическое списание. Неучтённое задание не отправляет расход в Spoolman.
