# Временная разблокировка: макет и нативный macOS GUI

Реализован вариант «Временная Разблок.» из
[отчёта Lazyweb](https://design.lazyweb.com/report/lazyweb/6f7990ab-5512-498c-9890-04d2939e1955/?source=create).
Просмотрен именно Mockup 1, 1375×1144. Макет сохранён в
`output/uid-temporary-unlock/spec.png`.

## Интерфейс

Диалог «Временно снять блокировку?» воспроизводит две карточки радиовыбора,
их текст и иерархию, два обязательных подтверждения, информационную строку,
кнопки «Снять блокировку» и «Отмена». По умолчанию выбрано «На 15 минут».
Для второго режима информационная строка меняется на напоминание подтвердить
назначения перед печатью. Имя принтера и содержимое доски остаются данными,
а не зашитыми в интерфейс значениями из изображения.

Сравнение проведено при размере 1375×1144: compare-first.png и compare-final.png.
После первого сравнения устранён лишний перенос описания второго режима,
уточнены ширины карточек, колонки доски, кнопка отмены и отступы. Сохранены
стиль доски, прозрачный фон диалога, размеры и порядок элементов макета.

## Поведение и сохранность учёта

- `15_minutes`: 900 секунд для переподтверждения. При истечении без завершённого
  подтверждения возвращается блокировка назначений/переноса/старта. Решение о
  недоказанном расходе не отменяется и не превращается в новое списание.
- `until_assignment`: окно без таймера, заканчивающееся после переподтверждения
  относящихся к прерванному заданию ручных назначений. До этого новая печать
  через учёт не допускается.
- Для заданий без ручных назначений нет ожидания невозможного ручного действия;
  последующий старт по-прежнему требует подтверждённых живых UID-наблюдений.
- Закрытие старого расхода, окно и журнал попыток записываются атомарно одним
  SQLite-владельцем. Уже списанное не изменяется. История старого задания
  остаётся защищённой от позднего расхода.
- Срок и состояние окна переживают перезапуск. Старый повтор запроса возвращает
  прежний результат, не продлевая срок. Возобновить истёкшее окно можно только
  новым подтверждённым решением с текущей версией и свежей проверкой принтера.
- Повтор с тем же идентификатором версии и другим режимом отклоняется.
- Частичный перенос нескольких катушек не позволяет начать новое задание на
  другом принтере до подтверждения всех необходимых назначений. При возобновлении
  истёкшего окна подтверждения затронутых катушек сбрасываются и на другом принтере.

Новые таблицы: uid_unlock_windows и uid_unlock_attempts. Таблица
uid_manual_resolutions сохраняет постоянное решение об учёте. Старые решения,
записанные до появления временных окон, не получают новый таймер задним числом.

## Нативная проверка

Два свежих запуска Python 3.9 / pywebview / Cocoa-WKWebView, окно «Tracker 2.0 ·
стенд». Только localhost и новые базы /private/tmp/uid-gui-bench-*.
Через управление настоящим окном проверены:

1. Открытие, начальный выбор 15 минут, выключенные галочки и недоступная кнопка.
2. Переключение второго режима и изменение пояснения.
3. Отмена без изменений, сброс режима и галочек при повторном открытии.
4. Одна галочка не включает отправку; две включают.
5. При тестовом print_stats=printing сервер отклоняет разблокировку.
6. После cancelled режим 15 минут сохраняется, показывается срок подтверждения.
7. Ручное переподтверждение завершает окно и убирает напоминание.
8. На новой базе второй режим сохраняется без дедлайна и показывает напоминание.

Проверены копии обоих SQLite: остатки 499702 и 299404 мг не изменены, списаний 0,
по одному решению; integrity_check=ok. В первом окне completed=1, во втором
completed=0, deadline=NULL (назначение намеренно оставлено неподтверждённым).

## Автоматические проверки

418 тестов прошли за 19.05 с. Новые тесты покрывают истечение, неизменный срок
при повторе, возобновление, завершение обоих режимов, смену режима при повторе,
перезапуск, отсутствие таймера у второго режима, защиту позднего расхода и
частичный перенос нескольких катушек.

Отдельно браузером на настоящем GUI bridge проверены возврат блокировки,
недоступность назначения, повтор старого запроса, возобновление с текущей версией,
переподтверждение и отсутствие повторной блокировки после завершения. Для этого
использованы управляемые часы только лабораторного launcher: +901 и +1802 секунды,
без изменения системного времени. 15 минут реального ожидания не выполнялось.

## Воспроизведение и ограничения

`/private/tmp/tracker-cancel-test-env/bin/python dev/labs/uid_gui_bench/run.py --window --resolution`
создаёт синтетическое прерванное задание в новой базе. `print-state.txt` и
`clock-offset.txt` находятся только в созданном временном каталоге; это фикстуры,
не API основного приложения. Без `--window` доступен тот же браузерный стенд.

Артефакты: `output/uid-temporary-unlock/` — spec.png, compare-first.png,
compare-final.png, confirmed.png, tests.txt, browser-results.json,
verification.json и три копии SQLite.

В этом этапе использованы нативный GUI и синтетический backend; два настоящих
процессных Klipper/Moonraker заново не запускались. Их предыдущая проверка
ручного разрешения описана в uid-manual-resolution-2026-11-10.md. Windows GUI
по-прежнему не проверен. Физическую остановку пользователь подтверждает сам;
диалог не посылает команды принтеру. Все стенды остановлены. Реальный принтер,
установленный Tracker, пользовательские настройки и база не тронуты.
