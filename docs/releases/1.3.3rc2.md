# 1.3.3rc2 — Windows GUI initialization fix

Test build based on 1.3.2, retaining the busy-lock handling from rc1.

The JavaScript API bridge exposed its native window as a public attribute. pywebview recursively inspected the WinForms object graph during initialization. A Windows CI reproduction reached maximum recursion depth and hung. Internal window, store and module references are now private; only hide, export_backup and import_backup are exposed.

Diagnostics now include process/thread identifiers, pystray and pywebview errors, unhandled thread exceptions, and window lifecycle events.

Windows CI now checks the real tray popup and window API using a temporary offline inventory without Snorca or a printer. This does not replace user verification. **Windows GUI on the affected user's machine remains UNVERIFIED**, as does real Snorca slicing on Windows.

## Проверка пользователем

1. Завершите предыдущие экземпляры Tracker через Диспетчер задач, поскольку их трей может не отвечать. Не удаляйте базу или lock-файл.
2. Запустите 1.3.3rc2 без Snorca. Откройте меню правой кнопкой мыши и проверьте открытие окна.
3. Закройте окно, снова откройте его из трея. Проверьте пункт выхода и последующий запуск.
4. Если проблема остаётся, пришлите новый tracker.log из `%LOCALAPPDATA%\SnapmakerSpoolTracker-Beta12`.

Не запускайте одновременно разные версии для учёта одного принтера. Перед обновлением рекомендуется экспортировать резервную копию.
