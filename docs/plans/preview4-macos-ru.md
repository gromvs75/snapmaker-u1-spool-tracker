# Preview 4: поведение окна macOS

Дата: 06.11.2026. Preview 3 не устранила исчезновение системной строки меню
по повторной проверке пользователя. Её обработчик принудительной видимости удалён.

Окно настроек теперь создаётся как NSPanel с nonactivatingPanel сразу при
инициализации. Открытие панели и запуск GUI больше не вызывают принудительную
активацию accessory-приложения. Панель допускает ввод, остаётся обычного уровня
(не поверх всех приложений) и не скрывается при потере активности. Содержимое
WKWebView явно присоединяется к панели. Политика без Dock сохраняется.

Проверка готового Mac-приложения: настройки, ввод и вставка адреса loopback,
Control-Right/Left, отмена подтверждения импорта, закрытие и повторное открытие.
Снимок окна сохранён с тестовой сборкой. Эта проверка не доказывает исчезновение
исходного бага во всех конфигурациях Spaces; необходимо подтверждение пользователя.

Основание: [Apple: nonactivatingPanel](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel).
Используется адаптер Cocoa backend pywebview; при обновлении pywebview требуется
повторить нативную проверку, включая диалоги и клавиатуру.

Также добавлена проверка числового IPv4: адрес с октетом вне 0–255 отклоняется
до сетевого запроса. Это не означает, что все возможные причины ошибки соединения
с реальным U1 устранены. Реальный принтер в этой проверке не использовался.

Отдельные приложение, каталог данных Preview4 и порт 8774. Установленный Tracker
и пользовательские настройки предыдущих версий не изменялись. Windows GUI
остаётся непроверенным. Публикация релиза не выполнялась.
