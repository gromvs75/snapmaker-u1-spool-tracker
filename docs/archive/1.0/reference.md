# Technical notes for v1.0.1 and unreleased v1.1 beta

The app has a tray process, one native pywebview window backed by a `127.0.0.1:8765` HTTP server, and a separate Orca post-processing process. Both share `spools_u1.json` in the per-user application data directory. The tray uses pystray `run_detached` with the same macOS `NSApplication`; pywebview owns the main GUI loop. Window close hides it, tray Quit destroys it and stops the monitor/server/icon. The tray command reliably reopens it. The embedded page polls `/api/data` every 2.5 seconds, updates live state in place, and protects focused/dirty form values. A browser can load localhost for troubleshooting, but native backup dialogs are unavailable there.

`storage.py` uses `filelock` on a stable lock file across threads/processes, reads under the lock, validates internal schema version 2, writes a temporary file, fsyncs, and atomically replaces the database. Schema 0 and 1 databases migrate on read. A damaged database is preserved and copied into `backups/`; no silent reset occurs.

`gcode.py` reads the file tail first, then streams a fallback if metadata is not near the end. It requires a valid per-tool `; filament used [g] = ...` line. `preflight.py` compares each active tool's requirement plus reserve with its assigned spool. The hook returns zero for OK or explicit Proceed Anyway, nonzero for Cancel, parse failure, or storage error. An allowed preflight stores a planned job with output filename, SHA-256 and size, four per-tool grams, four captured spool IDs, printer config, time and status. It never changes G-code or subtracts inventory on export.

The optional monitor polls stock Moonraker `/printer/objects/query?webhooks&print_stats` and `/server/history/list`. For a candidate history job it checks `/server/files/metadata` and hashes the read-only `/server/files/gcodes/<filename>` download. It requires matching basename, SHA-256, byte size, configured printer and preflight time. The history `job_id` plus `start_time` and printer form a persistent run key. Beta2 records a physical mapping, physical weights and spool IDs while the job is active; only a verified continuous run may debit them once on completion. A monitoring gap, app restart, unavailable/changed map, changed slot assignment, or enabled/unknown auto-replenishment sends the run to review. Cancelled/error jobs do not debit the planned total. Older completed jobs first seen after restart are never retroactively debited. The monitor makes no cloud requests.

The v1.1 beta start check uses the active history identity without requiring an Orca export plan. It reads the exact remote G-code into a bounded temporary file (512 MiB maximum), verifies size and modification metadata, parses per-tool usage, and compares it with currently assigned spools. Results are recorded in `last_preflight` and `last_guard`; unknown usage is never treated as zero. The default Warn only mode reads and alerts but sends no printer command. Off skips the start check. Strict is opt-in and, only after the monitor has observed an idle or terminal printer state, may send `POST /printer/print/pause` for a new risky or unverifiable job. It rechecks print state, filename, and persistent history run identity just before pausing. The dashboard exposes Resume Anyway and Cancel Print only for that exact Tracker-paused job; the API rechecks the same identity before each command. An already running job when the app starts is never automatically paused. Strict polls every two seconds rather than ten, but file transfer and verification can still finish after extrusion begins. The alpha's read-only detection was confirmed on one physical U1 for Orca Print and printer-screen starts; pause/resume/cancel remain simulator-tested only. These beta commands are not yet a validated hardware safety interlock.

In the physical beta1 test, the U1 logged the PAUSE request at 15:56:39 and started processing it at 15:56:54, after beta1's five-second HTTP timeout. The [test record](../../../dev/PRINT_START_GUARD_BETA_TEST.md) retains the evidence and limitations. The beta2 development source sends a single pause request from a separate thread with a 60-second control timeout so monitoring can continue. It records pending and uncertain outcomes, never retries an ambiguous command, hides decision controls unless the matching job is confirmed paused, and switches Strict to Warn only on uncertainty or restart during a pending command. Resume/cancel similarly record their pending state before sending and prohibit repeats if the result is unknown. A delayed request may still execute after a disconnect; the client cannot atomically bind it to a printer job. Do not start another print until that outcome is resolved. These changes are simulator-tested and have not been validated on physical hardware.

Beta2 reads `print_task_config.extruder_map_table` alongside `print_stats`, validates the first four logical entries, verifies the same mapping and active history identity before and after downloading the G-code, and sums weights that map to the same physical head. Missing, invalid or changed mapping produces an unverified check. The pre-export hook cannot know the final printer mapping and labels its direct-slot comparison provisional. Auto-replenishment may change during a print; beta2 requires it to be explicitly off whenever observed and marks uncertain runs for review, but polling cannot prove a preference did not change between observations. This remains a limitation, as do manual spool changes not reflected in Tracker. Physical remapping and beta2 printer control still require U1 testing.

The packaged macOS beta2 uses `SnapmakerSpoolTracker-Beta2` as a separate data directory. On its first launch it takes a locked, read-only snapshot of the regular Tracker inventory and printer settings, resets guard mode to Warn only, and clears copied plans, runs and transient state. Changes in the beta do not synchronize back. The regular and beta apps use the same local port and must not be run together; an Orca post-processing hook pointed at the regular app writes to the regular store.

JSON POST requests require an appropriate host, same origin when provided, `application/json`, and at most 64 KiB. User input is rendered with DOM text nodes. The tray menu refreshes after database changes. A second launch does not create another server/tray; it can restore a minimized window, but the tray command is the reliable reopen path after X.

`backup.py` defines a separate portable format: `backup_format: SnapmakerSpoolTracker`, `backup_version: 1`, app version, ISO-8601 export time, and `data`. `data` holds internal schema version, language, reserve, spools, slots, printer config, last preflight, plans, and runs; it omits live `monitor` and transient `last_guard` for v1.0.1 backup compatibility. Export reads a validated locked snapshot without rewriting the database, then atomically writes UTF-8 JSON to a native Save-dialog path outside the data directory. Import uses a native Open dialog plus confirmation, caps input at 10 MiB, checks the envelope and exact durable keys, and validates through `validate_db`. Under the same store lock, it saves the previous database to `backups/pre-import-*.json` before atomically replacing it. Invalid imports do not replace data. Monitor state is reset to disconnected when enabled or disabled otherwise, and guard mode is reset to Warn only so restoration cannot silently arm printer control. UI/tray update without restart. Raw legacy DB import is deliberately unsupported by this UI. Internal backups are not protection from uninstall cleaners that remove the entire data directory; users must export a portable file elsewhere.

For user setup, see [README](../../../README.md), [English manual](guide-en.md), and [Russian manual](guide-ru.md). CI runs tests and PyInstaller builds a Windows `.exe` (Edge WebView2 Runtime required for the GUI) and unsigned macOS `.app` wrapped in a ZIP. `dev/` and fixtures are not packaged. The alpha's read-only print-start check ran on one physical stock U1 with Orca Print and printer-screen starts. The beta's printer-control flow and Windows GUI still need physical/manual validation before a release decision.

Material mismatch detection is deferred because the current parser has no verified stable per-tool material metadata. Add it only after capturing representative Snapmaker Orca output and testing the mapping to T0–T3.
