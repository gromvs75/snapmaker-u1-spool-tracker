# QIDI и Anycubic: RFID 0.4.0, стенд Tracker 2.1

Добавлены QIDI Mifare Classic и Anycubic ACE Type 2. Bambu сохранён.
Это backend и программный стенд: реальный принтер, установленный Tracker и rc21
не изменялись. Новый GUI/EXE не собирался; Windows GUI с этим кодом не проверен.

## Что читается

| Формат | Данные метки | Что добавляется отдельно |
|---|---|---|
| QIDI | Коды материала, цвета, производителя; проверены PLA Matte/PETG и 4 цвета | Диаметр, плотность, номинальная и начальная масса |
| Anycubic ACE | SKU, материал, цвет, бренд-код, температуры, диаметр, номинальная масса, длина, скорость при наличии | Плотность, подтверждение новой катушки или второй стороны |
| Bambu | Прежние свойства и общий tray UID | Плотность; начальный остаток для использованной катушки |

QIDI открывается заводским ключом FF FF FF FF FF FF, читается блок 4.
Anycubic читается командой 0x30 по 4 страницы, страницы 0–31. Штатный файл
FM175xx не патчится; дополнительные операции выполняются в его потоке чтения.
Запись в RFID отсутствует. Данные публикуются отдельно от штатного формата U1.

Неизвестный код QIDI остаётся числом, материал/цвет — `null`; белый цвет,
масса и диаметр не подставляются. Автосоздание такой катушки блокируется.
Для Anycubic принимаются проверенные версии 0x64/0x65 с magic на странице 4.
Неопределённая ширина SKU обработана консервативно: требуется завершение строки
в первых 12 байтах. Более длинный SKU пока даёт только UID, а не угаданное изделие.

## Две метки одной катушки

В проверенных QIDI/Anycubic полях нет подтверждённого общего идентификатора двух
сторон. Поэтому новая метка сначала требует выбора: новая катушка либо вторая
сторона существующей. Совпадение материала, цвета или SKU не объединяет катушки.

Для первой метки нового рулона backend-настройка `confirmed_new_tags` содержит
её идентичность, например `qidi:chip:04123456`. Не следует автоматически добавлять
туда каждый увиденный UID: так снова появятся дубли второй стороны.

Для второй стороны используется явная backend-операция, когда принтер простаивает
и прежнее назначение катушки снято:

```python
ticket = owner.call('rfid_prepare', printer_id, channel)
owner.call('rfid_pair', ticket, existing_spool_id, confirmed=True)
```

Проверяются свежесть сканирования, соединение, свойства, задания, архив,
существующие связи и попытки удалённого создания. Уже зарегистрированные катушки
не сливаются. Привязка не меняет массу и ничего не пишет в Spoolman/RFID.
После неё оба UID узнаются автоматически, включая перезапуск и backup/restore.
Restore, как и раньше, выключает автоматические операции до нового включения.
Пары сохраняются в Tracker; при потере локальной базы требуется её backup или
повторная явная привязка. Одного SKU для восстановления пары недостаточно.

## Настройки стенда

В активирующем Klipper cfg лабораторного запуска:

```ini
[tracker_uid]
bambu_read_enabled: True
qidi_read_enabled: True
anycubic_read_enabled: True
```

Все три расширения по умолчанию выключены. Стенд сам добавляет опции после
лабораторного загрузчика. Это не инструкция установки на реальный U1;
следующая активация загрузчика пересоздаёт cfg со значениями по умолчанию.

Пример `rfid` для **новых полных стендовых катушек**:

```json
{
  "enabled": true,
  "allow_create": true,
  "send_usage": true,
  "new_spools": "nominal",
  "confirmed_new_tags": ["qidi:chip:04123456", "anycubic:chip:5330BDAD950001"],
  "densities": {"qidi:02": 1.32, "anycubic:AHPLPBK-108": 1.23},
  "diameters": {"qidi:02": 1.75},
  "nominal_weights": {"qidi:02": 1000}
}
```

Spoolman URL задаётся отдельно, режим — `send`. Для использованной катушки
нужен `new_spools: hold` и `initial_balances` по её идентичности. Для уже известной
катушки номинал не применяется повторно. Расход идёт через прежний журнал и Sender;
неоднозначный результат отправки не повторяется автоматически.

Значения плотности сверены с SpoolmanDB, но каталог не привязывает UID к рулону.
Например, у QIDI PETG есть несколько разновидностей с разными плотностями:
одного кода семейства недостаточно для безопасного автоматического выбора.
Свойства в настройках должны соответствовать фактической разновидности катушки.

## Воспроизведение и OFF

`dev/labs/uid_live_bench/multibrand_run.py` использует те же аргументы, что Bambu-стенд:
`--archive`, `--klipper`, `--driver`, `--dictionary`, `--spoolman`, `--spoolman-python`,
`--research`, `--output`. Работают настоящие локальные Klippy и Spoolman 0.27.1,
RF/SPI/GPIO/MCU имитируются. QIDI-карты синтетические по опубликованным кодам;
Anycubic использует три опубликованных дампа. Вторая сторона Anycubic синтетическая:
настоящей опубликованной пары с общим признаком не найдено.

Независимое отключение установленного стенда:

```sh
python3 -I /absolute/simulator/persistent/tracker-deployment/debug-loader-kit/disable-rfid.py \
  --simulator-root /absolute/simulator
```

Не нужны работающие Klipper/Moonraker или импорт extra. Изменение действует на
следующий запуск; текущий процесс не выгружается. Принтер и его службы инструмент
не обслуживает. Не создавайте маркер симулятора на реальном U1.
