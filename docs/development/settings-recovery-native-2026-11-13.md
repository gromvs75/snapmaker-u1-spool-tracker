## Этап 1: настройки и восстановление

`Session` управляет владельцем SQLite, подключениями UID и внедряемыми сборщиками.
Редактор GUI сохраняет до 32 принтеров: постоянный ID, имя, адрес Moonraker.
Нормализация адресов исключает дубли, пользователь/пароль в URL и неверные порты.
Изменение подключений требует их остановки. Исторические ID нельзя удалить этим
редактором; переименование и смена адреса сохраняют идентичность. Запуск/остановка
подключений явные. После открытия приложения подключения автоматически не запускаются.

Резервная копия — JSON-контейнер `tracker-uid-backup`, версия 1, с SQLite и SHA256.
Перед экспортом проверяются SQLite integrity_check и foreign_key_check. При импорте
проверяются формат, размер, хеш, целостность, связи, точная схема текущей версии и
настройки принтеров. SHA256 обнаруживает повреждения, но не удостоверяет автора файла.
Старые необёрнутые `.sqlite` этим GUI не принимаются; миграция форматов отдельно.

Восстановление:
1. Подключения и сборщики остановлены; HTTP-мост сериализует команды через Session.
2. Предварительный просмотр показывает числа катушек, заданий, списаний и операций.
3. Нужны явное подтверждение и неизменность текущей базы со времени проверки.
4. Перед заменой сохраняется `before-restore-<id>.json` рядом с тестовой базой.
5. SQLite backup API заменяет содержимое с сохранением блокировки единственного писателя.
6. До активации копии сбрасываются подтверждения назначений/наблюдений, активные задания
   теряют доверие к непрерывности, временные разблокировки удаляются. Старые held/pending/
   sending операции Spoolman становятся uncertain. Подключения остаются выключенными.

Восстановление при текущей отправке Spoolman (`sending`) запрещено. При ошибке проверки
текущая база не меняется. Откат к копии не восстанавливает физическое состояние катушек
или Spoolman: нужна ручная сверка. Неподтверждённые операции сами не отправляются.

## Этап 2: отдельное исследование автодозаправки

Добавлены только лабораторные `bench_transition.py` и `process.py` в
`dev/labs/uid_autorefill_boundary_bench/`. Производственные motion-валидаторы,
допуски и правила списания не менялись.

На отдельной паре Klipper/Moonraker воспроизведены синтетический runout T3,
служебный paused, mapping T3 → T1, движения двух головок, resume и completion.
Пакет с 2 мм движения до паузы специально задержан до paused. Отбор по статусу
в момент получения ошибочно относит 27 мм к служебному интервалу вместо 25 мм.
Это воспроизводимый контрпример фильтрации по времени получения, не объяснение
физического расхода реального U1.

Синтетические команды дают 25 мм по головкам и 12.84003 мм по общему счётчику
внутри перехода; затем приращения совпадают. Постоянная разница 12.15997 мм
воспроизведена намеренно как диагностический сценарий. Независимое объяснение
доступно только потому, что стенд сам задаёт команды и общую шкалу времени.
Его нельзя переносить на реальные журналы как поправку или доказанный алгоритм.

Процессный эксперимент: **6/6**, `output/autorefill-process/results.json` и исходные
motion/status журналы. Реальный сборщик, повтор history и переподключение не
разрешили списание: 0 дебетов, оба остатка 500000 мг. Исследовательская модель
также всегда возвращает `authorizes_debit=false`.

Открыто: происхождение расхода внутри реального перехода, согласованные временные
границы и полнота служебных движений. Совпадение 260 прежних сводок и последующих
приращений этого не доказывает. Первое предупреждение до доступного архива не объяснено.

## Этап 3: macOS и границы проверки готовности

В нативном Cocoa GUI проверены сохранение/повторное открытие настроек, системное
сохранение файла, выбор этого файла, проверка целостности, подтверждение и восстановление.
Временная база: `/private/tmp/uid-settings-native-20261113`.

Обнаружены и исправлены:
- WKWebView при запрещённых скачиваниях открывал JSON blob вместо диалога сохранения.
  В изолированной оболочке включён ALLOW_DOWNLOADS; повторное сохранение/восстановление прошло.
- Штатный macOS Quit вызывал обычное закрытие окна, а оно по политике трея отменяет
  закрытие. Пункт Quit/Cmd+Q направлен в явный quit. После исправления процесс завершился
  с кодом 0, включая выход после скрытия окна.
- Повторный close управляемого сеанса теперь безопасен.

Собран отдельный `.app` по `packaging/TrackerUidSettings.spec`:
`output/settings-dist/Tracker-2.0-Settings-Bench.app`.
PyInstaller 6.22.3, pywebview 6.2.1, pystray 0.19.5, framework Python 3.9.
Сборка запускается на отдельной базе, открывает настройки; второй экземпляр на той же
базе отклоняется блокировкой с кодом 1. Закрытие скрывает окно, Cmd+Q завершает процесс
с кодом 0. Это локальная стендовая сборка, не подписанный/нотаризованный релиз.

**Не считать проверенным:** фактическое открытие скрытого окна и выход именно через
пункт системного трея. Unit-проверка show/hide/quit проходит, но не заменяет такой
ручной/нативный прогон. Инструмент CUA дал длительную задержку и не предоставил надёжного
доступа к меню трея; это ограничение проверки, а не результат «passed».

**Windows EXE этого HEAD не проверен и не собран на Windows.** Actions не запускались:
пользователь требует отдельное разрешение на отправку интеграционной ветки. Старые
успешные Windows прогоны не являются доказательством для этого состояния.
Кроссплатформенный spec подготовлен, но Windows-часть остаётся неподтверждённой.

## Что ещё необходимо до готового приложения

- Новый launcher остаётся изолированным стендом. Без worker_factory доступны
  подключения UID; GUI явно сообщает, что сборщик расхода не подключён. Полная
  связка с двумя сборщиками проверена в `live.py` с синтетическими профилями.
  Автоматическую подготовку доказанного профиля реального задания этот этап не добавляет.
- Установленный/релизный entrypoint не переключался на 2.0. Существующий Windows
  `normal_launch.py` рассчитан на старую оболочку (закрытие завершало процесс) и должен
  быть адаптирован к политике трея перед следующей проверкой Actions.
- Не добавлены ключи API Moonraker и удаление исторического ID принтера.
- GUI ручной сверки Spoolman всё ещё отдельный будущий шаг; backend/API сохранены.
- Восстановление поддерживает точную текущую схему, до 32 МБ SQLite. Восстановление копий
  другой схемы/версии требует отдельной миграции, а не обхода проверки.
- Автодозаправка остаётся заблокированным исследовательским сценарием.

Продолжать с оставшихся проверок трея, полноценного launcher и Windows после отдельного
разрешения на push/Actions. Нельзя объявлять весь Tracker 2.0 готовым к выпуску.
