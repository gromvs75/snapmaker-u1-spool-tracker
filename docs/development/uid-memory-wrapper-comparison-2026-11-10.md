# UID: обёртка в памяти и патч — сравнение на стенде

Дата: 10 ноября 2026. Никаких подключений к U1, установок, изменений рабочей базы или
публикаций. Проверены те же снимки 1.3.0.168, 2.0.0.205, 2.1.0.157 из корпуса Bespok3d.

## Итог

159 тестов: 72 прежнего пути с патчем, 87 нового пути на неизменённых исходниках.
Результат: `output/uid-bridge-bench/memory-comparison-results.txt`.
Команда: `/private/tmp/tracker-uid-bench-env/bin/python -m pytest dev/labs/uid_bridge_bench -q`.

Для 2.0.0 выбрать **обёртку в памяти как основной кандидат реализации**, с жёстким
ограничением поддерживаемых исходников. Это выбор архитектуры по программным проверкам,
НЕ доказательство надёжности на физическом U1 и НЕ разрешение установки.

## Новый путь

`memory_bridge.py` наблюдает за тремя точками экземпляра FM175XXReader:

1. Выбор канала: запоминает номер в thread-local, начинает новый набор наблюдений.
2. Успешная активация карты: вызывает исходный метод, проверяет ATQA, CASCADE_LEVEL,
   SAK/каскадные биты и BCC, восстанавливает полный UID из каскадных блоков без байтов 88.
3. Итоговый callback чтения/очистки: передаёт исходные аргументы исходному потребителю,
   независимо отдаёт UID своему статусу через очередь reactor. Дополнительно обёрнут
   register_cb_2_card_info_deal, чтобы последующая штатная регистрация сохранялась.

UID копируется до аутентификации и NDEF. Никаких дополнительных команд радио, чтения
страниц NTAG или декодеров материала. Ошибка ключа/неизвестный формат у штатного detector
остаются ошибкой, но не уничтожают уже подтверждённый успешной активацией UID наблюдателя.
Если активации не было, UID не выдаётся. Если в одном цикле увидены разные UID — conflict.
При callback clear публикуется absent. Неуспешное чтение без UID — unreadable, не absent.

Исходный файл не меняется: тесты проверяют SHA-256 после каждого прогона. Полный штатный
цикл сканирования, активация с каскадами, повторы и callback выполняются настоящим кодом.
Подменены низкоуровневые ответы wakeup/anticollision/select, аутентификация, SPI/GPIO,
ожидания. Для оригинальной карты использован успешный ответ блока без проверки настоящей
подписи: проверяется сохранение аргументов, не подлинность криптографического декодирования.

## Проверки нового варианта

- UID 4, 7 и 10 байт, четыре канала, ведущие нули; 7-байтовая пустая NTAG.
- Одинаковые последовательности вызовов радио и оригинальных callback с обёрткой и без.
- Успешный исходный результат оригинальной карты не изменяется.
- Ошибка активации, BCC, случайный UID с префиксом 08, отсутствие карты.
- Отложенные и переупорядоченные события: старое чтение не оживляет очищенный канал.
- Выход из фонового потока через очередь; UID остаётся верным после reset общего буфера.
- Отключение восстанавливает исходные методы/callback и гасит очередь старого поколения.
- Поздняя регистрация штатного callback сохраняется при отключении.
- Чужое изменение hook после подключения не затирается при отключении: требуется рестарт.
- Повторная установка своей обёртки и неизвестный хеш файла отвергаются.
- Ошибка enqueue не прерывает штатный callback, локальный кэш инвалидируется.

## Сравнение

| Критерий | Патч считывателя + UID-адаптер | Обёртка в памяти |
|---|---|---|
| Изменение исходного файла драйвера | Да | Нет |
| Полный образ альтернативной прошивки | Не нужен | Не нужен |
| Пустая NTAG | Дополнительное чтение страниц, извлечение UID до NDEF | UID уже доступен при штатной активации |
| Mifare после ошибки ключа | Требуется активировать fallback | UID сохранён ещё до проверки ключа |
| UID 7/10 байт | Данный Mifare fallback берёт только первые 4 байта | Полный UID восстановлен в симуляции каскадов |
| Влияние на штатный тракт | Меняется результат обработки неизвестной карты | Аргументы штатных callback и команды сохранены в тестах |
| Зависимость от версии | Контекст diff и регистрируемые hooks | Имена private-методов и семантика буфера/цикла |
| Откат | Восстановление файла/конфига | Отключение своего config/module и рестарт Klipper |
| Главный риск | Неподходящий патч, конфликт с другими правками | Порядок подключения, уже работающий поток, чужие обёртки |

Патч добавляет явные точки расширения, но в нашей UID-only задаче вмешивается больше.
Обёртка точнее соответствует условию «не менять штатные файлы» и позволяет взять
идентичность до декодирования. Ни одна схема не становится автоматически совместимой
с новой прошивкой: неподдерживаемый хеш должен отключать RFID-функцию с сохранением
ручного режима Tracker. Автоматически переключаться с обёртки на патч запрещено.

## Минимальный будущий состав и ограничения

Кандидат: один `tracker_uid.py` в extras и секция конфига. Собственный get_status,
без изменения filament_detect/print_task_config, без базы на U1, без Spoolman, без
Bespok3d daemon, без изменения pressure advance. Обёртка меняет поведение процесса
в памяти, хотя оставляет исходники нетронутыми; это всё ещё дополнение к штатному ПО.

Прототип НЕ готов к установке: attach/detach предполагают остановленное сканирование.
Нужно реализовать и испытать настоящий load_config/ready/shutdown и момент подключения
до первого сканирования, потокобезопасный handoff и отключение, timeouts/свежесть,
Moonraker GET/subscribe, привязку к printer_id, полный контракт статусов и диагностики.
В тесте очереди использован контролируемый enqueue, не реальный Klipper reactor.

Проверка хеша файла сама по себе не обнаруживает ранее установленную чужую обёртку
метода. Перед живым подключением нужна проверка происхождения bound methods, отсутствие
конкурирующих плагинов и отказ при неоднозначности. Тест конфликта покрывает чужое
изменение ПОСЛЕ attach, не произвольную стороннюю модификацию до attach.

Нельзя выполнять установку/горячее отключение во время печати. Сначала стенд жизненного
цикла и отката, затем отдельное разрешение на свободный U1. Неизвестные версии и
физическая несовместимость меток не обходятся предположениями. ISO15693 не обещается.
