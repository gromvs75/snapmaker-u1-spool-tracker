# GUI 2.0: подготовка Windows-проверки — 10 ноября 2026

**Фактическая проверка GUI на Windows не выполнена.** Доступная машина — macOS;
Windows VM/удалённый стенд не обнаружены. Пользователь подтвердил, что Windows-
стенда нет. Поэтому временная разблокировка, перенос и защита учёта именно в
Windows GUI остаются непроверенными. Прежняя пометка о Windows сохраняется.

## Что удалось исправить и подготовить

1. Лабораторный launcher использовал абсолютный `/private/tmp`, отсутствующий на
   обычной Windows. Теперь tempfile выбирает временный каталог ОС; каждый запуск
   создаёт новую отдельную базу. Валидационный запуск действительно создал каталог
   uid-gui-bench-* в системном TEMP macOS, а не в жёстко заданном пути.
2. GUI bridge читал HTML без encoding. Теперь задан UTF-8 явно: русские строки
   больше не зависят от локальной кодировки чтения Python на Windows.
3. Для Windows в pywebview запрашивается Edge Chromium; ветка на Windows пока
   не исполнена. Наличие и поведение WebView2 должны проверяться на настоящем
   стенде; совместимость старого MSHTML не заявляется.
4. Добавлены run-info.json (ОС, Python, запрос native GUI, renderer и факт возврата
   event loop) и verification.json со снимком SQLite после закрытия. Они являются
   материалами проверки, а не автоматическим заключением об исправности GUI.
5. Подготовлены Start-Windows.ps1 и WINDOWS.md в dev/labs/uid_gui_bench. Скрипт
   требует уже подготовленное отдельное Windows-окружение, ничего не устанавливает
   и не меняет системные настройки. Использует случайный loopback-порт и новую
   базу; установленный Tracker и пользовательские базы не ищет.

## Что реально проверено здесь

На **macOS** прошли 48 целевых тестов (0.40 с): временное окно, истечение,
идемпотентность, ручное разрешение, поздняя история, lifecycle, перенос и его
транзакционные блокировки. Это повторная регрессия ядра, не Windows-проверка.

Запущен изолированный HTTP-стенд --resolution --port 0. HTML получен с localhost,
Content-Type содержит charset=utf-8, русские строки прочитаны без искажения.
После остановки сохранены run-info.json и verification.json; списаний 0.
Нативное Windows-окно, PowerShell-скрипт, WebView2, DPI, фокус и drag-and-drop
на Windows в этой сессии не запускались.

Артефакты: output/uid-windows-readiness/tests-macos.txt, http-smoke.json,
run-info.json и verification.json. Инструкция Windows описывает проверку обеих
галочек, обоих режимов, отказ при printing, срока +901/+1802 секунд, переноса,
остатков, клавиатуры и перезапуска; тесты повторной истории дополняют реальные
взаимодействия, но не подменяют их.

## Что требуется для завершения

Доступ к отдельной Windows VM/машине с интерактивным рабочим столом, подготовленным
Python/pywebview/filelock и WebView2. Только после фактического выполнения сценариев
и сохранения доказательств можно снять статус «Windows GUI не проверен».
Новая виртуальная машина не создавалась, ПО и компоненты ОС не устанавливались.

Локальный стенд остановлен. Реальный принтер, установленный Tracker,
пользовательская база и настройки не затрагивались. Релиз не публиковался.
