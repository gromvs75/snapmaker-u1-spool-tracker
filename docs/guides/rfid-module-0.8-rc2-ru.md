# RFID-модуль 0.8.0 для Tracker 2.1.0rc2

Этот отдельный архив предназначен для **установки на офлайн-стенд**, отключения и
отката. Реальный U1 при подготовке не используется. Это не универсальный установщик
для работающего принтера: CLI намеренно отвергает корень `/`. Не обходите эту проверку.
Для будущей установки на устройство ещё нужны сверка его драйвера, путей и управления
службами, затем отдельное аппаратное испытание. Готовность программного стенда не
означает проверки радиоканала настоящего U1.

## Что находится в архиве

- `tracker_uid.py` — модуль Klipper `0.8.0-roll-identity-bench`.
- `rfid_u1_trial.py` — установщик `0.7.0-trial`, также выполняющий OFF и откат.
  Версии разные, потому что это два отдельных компонента.
- `README-RU.md` и `ИНСТРУКЦИЯ-RU.txt` — эта инструкция.
- `manifest.json` — версии, привязка к rc2 и SHA-256 всех вложенных файлов.
- `verify_package.py` — проверка целостности без подключения к принтеру.
- Файлы `*-VERIFIED.json` — результаты проверок, когда включены в итоговый архив.
  Хеш проверяемого ZIP в них относится к пакету до добавления отчётов;
  модуль и установщик в итоговом архиве остались побайтно теми же.

Модуль побайтно совпадает с исходником, использованным при подготовке приложений
2.1.0rc2, коммит `01cfe7b7503dac3f6b2df4d0c69813e54cac4dd3`.
SHA-256 модуля: `d692443119be56ec02f795bd9906a30a45f827c9848de8ae9b7effb906d73e22`.
Протокол статуса — `schema_version: 1`, объект Klipper `tracker_uid`.

## Что делает модуль

Он подключается к штатному `fm175xx_reader` в памяти; файл штатного драйвера не
переписывает. Перед вмешательством проверяет хеш и методы драйвера. Передаёт Tracker
UID, состояние канала и доступные свойства материала. Новая катушка подтверждается
в приложении, учёт и SpoolmanDB остаются в Tracker. На метки остаток не записывается.

Декодеры: Bambu, QIDI, Anycubic, Creality, Elegoo, TigerTag, Generic JSON/NDEF,
OpenTag3D и OpenPrintTag на поддерживаемом Type 2 носителе. Это не обещание чтения
каждого изделия бренда. ISO15693 заводских меток Prusa этот reader не поддерживает.
При неизвестном содержимом могут быть доступны только UID или ошибка декодирования.

Разные UID Bambu связываются по общему ID блока 9. Для OpenPrintTag используется
явный `instance_uuid`; при его отсутствии — ручная привязка второй метки.
Материал, цвет, SKU и номер партии сами по себе не объединяют физические катушки.

## Подготовка

1. Распакуйте весь архив в отдельную папку на компьютере стенда.
2. Нужны Python 3.11 и POSIX-система (проверено на Mac; установщик использует
   POSIX-блокировку файлов). Windows EXE Tracker может использовать данные модуля,
   но этот Python-установщик не запускается непосредственно в Windows.
3. В терминале перейдите в распакованную папку и выполните:

   ```sh
   python3 -I verify_package.py
   ```

   Ожидается `OK`. Хеши обнаруживают изменение файлов; это не цифровая подпись.
4. Подготовьте отдельную офлайн-копию файловой системы U1. В ней должны быть:

   ```text
   home/lava/klipper/klippy/extras/fm175xx_reader.py
   home/lava/printer_data/config/printer.cfg
   ```

   Также нужны файлы всех include. Процессы стенда должны быть остановлены.
   Папку такого стенда обозначим `/absolute/offline-u1`; замените этот путь
   своим абсолютным путём. Это НЕ IP-адрес и НЕ каталог установленного Tracker.
   На Mac используйте канонический путь, например `/private/tmp/...`, а не `/tmp/...`.

Установщик закреплён за драйвером из официальных исходников U1 **2.1.0.157**,
SHA-256 `ce7363f8b512e5474d18bd57cdf0660e6e2df57dc256e22f743b3b28c1b70be8`.
Другой хеш требует разбора, а не добавления в разрешённый список. `.debug`, симлинки,
специальные файлы, конфликтующие include и ранее установленный extra блокируют план.

## Установка на стенде

Сначала подготовьте план (модуль пока не устанавливается):

```sh
python3 -I rfid_u1_trial.py plan --offline-root /absolute/offline-u1 --module tracker_uid.py --formats bambu,qidi,anycubic,creality,elegoo,tigertag,generic_ndef,opentag,openprinttag > /absolute/rfid-plan.json
```

Проверьте, что команда завершилась без ошибки, а план называет именно ваш стенд.
Для узкого первого испытания можно использовать только `--formats bambu`.
Выбранные форматы записываются в план; `install` применяет именно его.

```sh
python3 -I rfid_u1_trial.py install --offline-root /absolute/offline-u1 --module tracker_uid.py --plan /absolute/rfid-plan.json
```

Ожидается `state: installed`. При изменении драйвера, модуля или конфигурации после
планирования установка отклоняется — сначала сформируйте новый план.

Установщик сохраняет исходные сведения и собственную независимую копию в
`home/lava/printer_data/tracker-rfid-recovery`, затем добавляет необязательный include
перед SAVE_CONFIG. Включающий конфиг записывается последним. `.debug`, init-скрипты
и калибровки не меняются. Python-пакеты на принтер не устанавливаются.

Запуск Klippy выполняет управляющий процесс стенда, не установщик. Проверка после
запуска: Klippy в `ready`, объект `tracker_uid` существует, его статус содержит
`module_version: 0.8.0-roll-identity-bench`, `schema_version: 1`, `state: ready`.
Стенд с имитацией только файловой системы без электроники не проверяет чтение RFID.

Подключите Tracker 2.1.0rc2 только к Moonraker-симулятору этого стенда. Сначала
проверьте новую метку и подтверждение катушки, затем другую сторону и возврат остатка.
Каталог SpoolmanDB не нужен модулю; он уже встроен в приложение rc2.

## Быстрое отключение, даже когда Klipper не запускается

Используйте сохранённый инструмент внутри **офлайн-копии**:

```sh
python3 -I /absolute/offline-u1/home/lava/printer_data/tracker-rfid-recovery/rfid_u1_trial.py disable --offline-root /absolute/offline-u1
```

Ожидается `state: disabled`, `effective: next-klipper-start`. Команда не требует
работающих Klipper, Moonraker, Tracker, исходного ZIP или импорта повреждённого модуля.
Она убирает включающий конфиг, сохраняя его копию для диагностики. Повтор допустим.
Уже загруженный код из памяти не выгружается: нужен следующий запуск Klippy стенда.

После запуска ожидаются `ready` и отсутствие объекта `tracker_uid`. Если ошибка
сохранилась, она может находиться вне этого дополнения; сохраните журнал стенда.

## Полный откат

```sh
python3 -I /absolute/offline-u1/home/lava/printer_data/tracker-rfid-recovery/rfid_u1_trial.py rollback --offline-root /absolute/offline-u1
```

Ожидается `state: rolled-back`. Сначала выполняется OFF, затем удаляются только
собственный include и модуль. Новые изменения остального конфига, в том числе
калибровки, сохраняются. Повтор допустим; журнал восстановления остаётся.
Изменённый модуль сохраняется как `retained-module.py` для диагностики.
При неоднозначно отредактированном собственном include откат останавливается после
OFF с `review-required`; не заменяйте весь `printer.cfg` старой копией вслепую.

Если файлы восстановления утрачены, независимый откат этим инструментом не гарантирован.
Сохраните всю папку recovery до удаления стенда.

## Что происходит при перезагрузке штатного U1

В исследованной модели штатная загрузка без `.debug` очищает системный слой.
Модуль и включающий конфиг исчезают вместе; оставшийся необязательный include
не препятствует запуску. Этот пакет не обеспечивает постоянный автозапуск после
перезагрузки устройства. Потеря только модуля при оставшемся конфиге может остановить
Klipper — такой сценарий включён в проверку OFF.

## Границы совместимости

Проверяются архив, настоящий процесс Klippy, закреплённый штатный драйвер и протокол
rc2, с имитацией RF/SPI/GPIO/MCU. Проверки приложения используют временную базу и
локальный Spoolman. Это совместимость программных компонентов, не подтверждение
текущей прошивки вашего физического принтера. Новая прошивка этим архивом не прошивается.

На стенде проверены семь сценариев загрузки/OFF/отката, в том числе ошибка синтаксиса,
пропавший модуль, испорченный конфиг, недоступный API и отсутствие процесса Klippy.
Калибровка сохранялась. Пройдены 204 профильных теста. С настоящими процессами
Klippy и Spoolman проверены Bambu/OpenPrintTag: подтверждение, списание 20 г,
вторая метка, перезапуск, восстановление бэкапа и разделение разных рулонов одного цвета.

Дополнительно готовое Mac-приложение rc2 получило неизменённый статус работающего
модуля через локальный мост-симулятор Moonraker: Bambu PLA / C12E1F, создание
840,123 г, возврат остатка 820,123 г по другому UID и после перезапуска приложения.
В этой отдельной проверке 20 г списал сам стенд через API Spoolman; учёт Tracker
проверен предыдущим сценарием. Новый Windows EXE для этого архива не собирался:
используется прежний rc2 того же коммита. Его GUI проверялся при выпуске rc2;
связка Windows EXE с живым Klippy в этой проверке повторно не запускалась.

Для будущей установки на настоящий U1 потребуется отдельный этап подготовки:
прочитать его версию и хеш драйвера, сверить файловую структуру и механизм остановки
служб, сохранить резервную копию и проверить восстановление доступа. Сейчас такой
доступ не выполняется. Не переносите команды офлайн-стенда на `/` и не включайте `.debug`.
