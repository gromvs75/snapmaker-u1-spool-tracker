# RFID 0.7: установка и откат на офлайн-копии U1

Это пакет репетиции установки, не команда для рабочего принтера. Проверяется файловая структура U1 2.1.0.157 и запуск настоящего Klippy на компьютере с имитацией электроники. CLI требует `--offline-root`, отвергает `/` и не содержит SSH, управления службами или прошивки. Физическая установка и чтение заводских катушек пока не проверены.

## Выбранный режим первого испытания

Модуль и включающий конфиг размещаются рядом в штатном каталоге extras. В `printer.cfg` перед SAVE_CONFIG добавляется необязательный include с точным шаблоном имени. Маркер `.debug` и init-скрипты не меняются. Наличие `.debug` заранее отклоняется: оно нарушило бы ожидаемое отключение после очистки системного слоя.

В исследованной штатной модели загрузки без `.debug` системный слой очищается: исчезают и модуль, и его включающий конфиг. Необязательный include остаётся без совпадения и не требует отсутствующий модуль. Это сознательно временная установка для первого испытания, а не постоянный автозапуск. Потеря одного только модуля при оставшемся конфиге может остановить Klipper — для этого есть независимый OFF.

Установщик не считает отсутствие PID-файла доказательством остановки службы. Поэтому доступен только офлайн-режим. Перед переносом на устройство всё ещё нужны проверка актуальных путей/драйвера, согласованная остановка служб и аппаратное испытание. Полный OEM этим пакетом не копируется и не восстанавливается.

## Репетиция

Нужен Python 3.11 и отдельно подготовленная копия файловой системы. В ней должны быть реальные пути относительно корня копии:

- `home/lava/klipper/klippy/extras/fm175xx_reader.py`;
- `home/lava/printer_data/config/printer.cfg` и файлы его include.

Поддерживается закреплённый драйвер 2.1.0.157 с SHA-256 `ce7363f8b512e5474d18bd57cdf0660e6e2df57dc256e22f743b3b28c1b70be8`. План проверяет дерево include и хеши. Нельзя добавлять другой хеш только ради обхода проверки. Пути с символическими ссылками и специальными файлами отклоняются.

Из распакованного пакета, только для подготовленной офлайн-копии:

```sh
python3 -I rfid_u1_trial.py plan --offline-root /absolute/offline-u1 --module tracker_uid.py --formats bambu > /absolute/plan.json
python3 -I rfid_u1_trial.py install --offline-root /absolute/offline-u1 --module tracker_uid.py --plan /absolute/plan.json
```

Перед `install` просмотрите план. Изменение драйвера, модуля или файлов конфигурации делает план недействительным. По умолчанию включается чтение Bambu; допустимые имена форматов: `bambu,qidi,anycubic,creality,elegoo,tigertag,generic_ndef,opentag,openprinttag`. Их поддержка не гарантирует чтение всех изделий каждого бренда.

До активации сохраняются исходный конфиг, запись установки и независимая копия инструмента в `home/lava/printer_data/tracker-rfid-recovery`. Конфиг активации записывается последним. Инструмент не запускает Klipper — это делает управляющий процесс стенда.

## Отключение при неработающем Klipper

Команды из сохранённой копии не требуют исходного ZIP, Tracker, Moonraker, импорта RFID-модуля или API Klipper:

```sh
python3 -I /absolute/offline-u1/home/lava/printer_data/tracker-rfid-recovery/rfid_u1_trial.py disable --offline-root /absolute/offline-u1
python3 -I /absolute/offline-u1/home/lava/printer_data/tracker-rfid-recovery/rfid_u1_trial.py rollback --offline-root /absolute/offline-u1
```

`disable` убирает только включающий конфиг, сохраняя его для диагностики. Действует при следующем запуске Klipper, не выгружает код из памяти работающего процесса. Повтор безопасен.

`rollback` сначала отключает RFID, затем удаляет свой include и модуль. Поздние изменения остального конфига, включая калибровку, сохраняются. Изменённый модуль сохраняется для диагностики. Если собственный include отредактирован неоднозначно, откат останавливается после отключения и требует разбора. Исходная копия и журнал остаются; восстановление всего старого `printer.cfg` поверх новых калибровок не выполняется.

## SpoolmanDB в следующем кандидате Tracker

В исходниках Tracker добавлен локальный снимок 10 058 изделий. Каталог работает без Интернета и предлагает плотность, диаметр и номинальную массу по бренду, материалу, точным цветам и известным параметрам. При нескольких совпадениях поля требуют ручной проверки; неизвестные свойства не угадываются. Восстановление остатка по UID не зависит от наличия каталога.

Это предложение для подтверждения, не доказательство идентичности изделия или физической катушки. Остаток вводится отдельно; две метки привязываются явно. Источник и версия предложенных параметров сохраняются в карточке и резервной копии. SpoolmanDB не является каталогом UID. Совпадения с неизвестным цветом/восьмизначным цветом не подставляются автоматически.

Эти изменения ещё не находятся в выданных ранее Mac/Windows архивах 2.1.0rc1. Они проверяются в рабочей копии перед следующей сборкой.
