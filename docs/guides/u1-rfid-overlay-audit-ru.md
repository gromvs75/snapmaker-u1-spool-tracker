# U1: диагностика системного слоя и процессов без установки

Это следующий шаг после сверки RFID-драйвера. Он **ничего не устанавливает,
не меняет конфиги, не останавливает службы и не перезапускает принтер**.
Пароль вводится только в вашем Terminal. Его не нужно присылать в чат.

## Для текущего рабочего checkout на Mac

Вставьте одну команду в Terminal. Она передаёт Python-код через stdin SSH,
выполняет его без создания файла на U1 и сохраняет JSON **на Mac**:

```sh
ssh -T -o StrictHostKeyChecking=yes -o HostKeyAlgorithms=ssh-ed25519 -o ConnectTimeout=5 lava@192.168.2.133 'python3 -I -B -S - --read-only-u1' < '/Users/viktor/snapmaker-tracker/output/spoolman-delivery-2.0/scripts/rfid_readonly_audit.py' > '/Users/viktor/snapmaker-tracker/output/spoolman-delivery-2.0/output/u1-rfid-readonly/overlay-service-audit.json'
```

В этой подготовленной среде каталог результата уже существует, файл пока пуст:
автоматическая попытка без пароля получила `Permission denied (publickey,password)`.
Повтор команды заменяет **только этот диагностический файл на Mac**.
Если хотите сохранить прежний отчёт, укажите другое имя после `>`.

Дождитесь возвращения приглашения Terminal. Затем можно передать файл
`output/u1-rfid-readonly/overlay-service-audit.json` для анализа. При ошибке SSH
файл может остаться пустым — это не успешная диагностика.
Если SSH сообщает об изменении ключа узла, остановитесь: не удаляйте known_hosts
и не отключайте StrictHostKeyChecking для обхода проверки.

Для другого checkout замените локальные пути, для другого принтера — адрес
и пользователя. Файл скрипта: `scripts/rfid_readonly_audit.py`.
Требуется Python 3 на U1; используется только стандартная библиотека.

## Какие данные собираются

- Хеши известных init-скриптов, cgroup helper, updater и RFID-драйвера.
  Их исходный текст в JSON не включается и не исполняется.
- Метаданные файлов `/oem/overlay/upper`: путь, тип, права, владелец,
  размер, хеш обычных файлов в пределах лимита, цели ссылок.
- Видимые имена extended attributes и хеши их значений. Цель — заметить
  особенности overlay; отсутствие видимых атрибутов не доказывает их отсутствие.
- Состояние маркеров сохранения, таблица монтирования, boot ID и PID-файл.
- Два наблюдения процессов Klipper/Moonraker/lmd: PID и время рождения процесса.
  Полные командные строки, environment и содержимое пользовательских конфигов
  не выводятся. Ни Tracker, ни SQLite, ни Spoolman не открываются.

Ссылки внутри верхнего слоя не обходятся. FIFO, сокеты и устройства не открываются.
Ограничения по умолчанию: 10 000 записей, глубина 64, хеширование до 2 МиБ одного
файла и 32 МиБ суммарно, программный предел обхода 15 секунд. Предел времени
проверяется между операциями и не является гарантированным таймаутом ядра.
При ограничении, отказе доступа, смене файла или недоступных атрибутах отчёт
помечается неполным. Не запускайте с `sudo` ради получения «зелёного» результата.

## Что этот отчёт НЕ разрешает

Инвентаризация работающего принтера не атомарна и не заменяет резервную копию.
Два одинаковых наблюдения PID не доказывают, что watchdog/lmd не перезапустит
Klipper позже. Отсутствие процесса не означает разрешения менять конфиг.

Поэтому `installation_allowed`, `stopped_proven` и `exclusive_control_proven`
всегда остаются `false`. Они не меняются автоматически даже при совпадении
драйвера, исправном PID-файле и полном обходе. Физическая установка и перезапуск
остаются отдельным, пока не разрешённым действием.
