## Итог этапа

Лабораторный откат теперь учитывает изменения за пределами Klipper и отказывается
восстанавливать старую копию поверх изменившейся прошивки. Подготовлен отдельный

**Это пакет только для маркированных симуляторов, не установщик для реального U1.**

## Что изменено

| Сценарий | Поведение | Проверка |
| --- | --- | --- |
| Чужой файл, удаление, изменение содержимого/прав, каталога или ссылки вне Klipper | Отключить собственную интеграцию; оставить системное сохранение и журнал для разбора | Файловые тесты; добавленный файл — оба процессных стенда |
| Чужие временные изменения существовали до установки | Не включать сохранение всего слоя автоматически | Файловой тест |
| Сохранение уже включено владельцем | Не удалять его маркер при откате RFID | Прежний и новый файловые тесты |
| Обновление может удалить чужие изменения | Заблокировать подготовку обновления, потребовать их сохранения и разбора | Файловой тест |
| Изменился базовый системный образ или его конфиг | Заблокировать старый откат до любых записей; не переустанавливать модуль | Три файловых сценария: Klipper, прочая система, конфиг |
| Специальный файл или hardlink | Отказать, не пытаться читать FIFO и не игнорировать файл | Файловые тесты |
| Повреждены файлы пакета восстановления | Отказ до импорта его кода и изменения стенда | Запуск отдельного процесса |
| Tracker/checkout недоступны | Отдельный Python-процесс читает постоянный журнал и выполняет откат | `python -I`, отдельный каталог, также оба Klipper/Moonraker |

Инвентаризация охватывает два моделируемых дерева: `klipper/` и `system/`.
Сохраняются хеши файлов, тип, права, UID/GID и цели ссылок. Ссылки не обходятся.
Отсутствующая запись отражает удаление. Отдельно сравнивается исходное дерево
прошивки вместе с исходным конфигом, поэтому совпадения одного RFID-драйвера
недостаточно для разрешения старого отката.

Пакет **не удаляет и не восстанавливает чужие файлы**. В процессном сценарии
стендовый владелец явно удаляет созданный им тестовый файл; только затем повторный
откат снимает собственный маркер. Это не автоматическое «исправление» чужих изменений.
Манифест с хешами обнаруживает случайное повреждение, но не является цифровой подписью.

## Что ещё не доказано

Это материализованная модель, **не полная копия фактического overlay U1**.
Она не моделирует kernel whiteouts, opaque directories, ACL/xattrs, границы
монтирования, параллельную запись системных служб и реальные отключения питания.
Python cache Klipper исключён из сравнения. Нет автоматического переноса старого
лабораторного журнала schema 1: его откат требует разбора, а не угадывания.

Внешний OTA не проходит через наш `prepare-update` принудительно. Потеря только
`.debug` при сохранённом include по-прежнему опасна; этот отказ намеренно остаётся
в тестах. Реальный updater, MCU, S60klipper и watchdog/lmd не запускались.
Следующий необходимый шаг перед предложением физической установки — проверить
реальную область системного слоя и процедуру управления службами/восстановления.
До этого нельзя представлять включение `.debug` как готовый безопасный установщик.

В этом этапе не было даже чтения с реального U1. Установленный Tracker,
пользовательская база и Spoolman не открывались. GUI, языки, UID-observer,
производственный учёт и основной установщик не менялись. Приложение остаётся
**2.0.0rc17**; новый app/EXE не собирался. Автодозаправка не разблокирована.
Ничего не отправлялось в GitHub, не публиковалось и не объединялось в main.
