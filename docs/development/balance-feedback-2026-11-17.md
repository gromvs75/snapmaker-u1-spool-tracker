# Корректировка остатка и сохранённая проверка запуска — rc13

Контрольная точка: `checkpoint/2.0-before-balance-feedback-20261117` (`6b22fc9`).
Ветка: `integrate/2.0-graphite-ui`. Изменения локальные, без публикации.

## Причины

1. `DesktopInventory.execute` сравнивает ревизию всей библиотеки и назначений.
   Она включает настройки, остатки, назначения и поколения соединений. Если
   состояние изменилось после загрузки формы, сервер возвращает 409 и не пишет
   остаток. Ранее обработчик показывал системный alert «Обновите экран» и оставлял
   старую форму. Живой опрос обновляет телеметрию, но не должен незаметно заменять
   данные редактируемой формы. Конкретный источник изменения в пользовательском
   запуске не установлен: пользовательская база и журналы не открывались.
2. Предупреждение обзора использует сохранённый снимок проверки запуска.
   Он содержит остаток на старте и не пересчитывается при редактировании катушки.
   Даже для завершённой печати с тем же именем файла он выглядел текущей тревогой.
3. Изменение остатка, подтверждение физического назначения и ручной учёт задания
   являются разными действиями. Первое не подтверждает назначение и не закрывает
   задание. Автоматически превращать корректировку в списание задания нельзя.

## Исправление

- Перед открытием корректировки загружаются свежие данные. Ревизия фиксируется
  для этой формы и не заменяется незаметно последующим опросом.
- Остаются чекбокс и кнопка сохранения; лишнее второе окно подтверждения убрано.
- При конфликте ревизии форма сама загружает новый остаток, сохраняет введённое
  число, снимает подтверждение и сообщает: изменение **не сохранено**. Следующая
  запись требует нового явного подтверждения. Автоматического повтора нет.
- При успехе обновляются данные приложения и выводится «Остаток сохранён».
- Потеря ответа обозначается как неизвестный результат, ввод блокируется до
  проверки того же запроса. Повтор сохраняет request ID и получает duplicate,
  если первоначальный запрос был выполнен. Новая операция не создаётся.
- Иные запреты backend (активное задание, Spoolman и т. д.) не обходятся.
- Для прошлой/завершённой печати проверка запуска находится в нейтральном
  свёрнутом блоке «Проверка при старте — сохранённый результат». Внутри сохранены
  исходные причины и числа. При текущей printing/paused предупреждение и действия
  остаются видимыми. Изменение остатка не делает неподтверждённое назначение
  подтверждённым.
- Новые сообщения переведены на RU/EN/DE/UK/ES. Правила учёта не менялись.

## Проверки

- Целевые тесты: 15 passed (`output/balance-feedback-targeted.log`).
- Конфликт + потеря ответа/повтор + исторический/текущий статус: 1 passed
  (`output/balance-feedback-loss.log`).
- Полная регрессия: 905 passed, 3 skipped, 1 failed за 152,85 с
  (`output/balance-feedback-regression.log`). Единственное падение — ожидаемая
  версия rc12 в тесте запуска при фактической rc13. Ожидание исправлено;
  весь модуль запуска повторно: **4 passed** (`output/balance-feedback-launch.log`).
  После этой правки менялся только тест, исходники сборки не менялись. Полный
  набор повторно не запускался. Три пропуска требуют закреплённого Plater.cpp
  либо специальных профилей macOS / loopback-only sandbox.
- Упакованный rc13: 8 групп проверок, все прошли. Искусственная копия 1.3.3,
  временный профиль, loopback Spoolman. Проверены конфликт и новая явная запись
  через API и HTML самого .app, пять языков, прежние окна, отсутствие новых
  списаний и отправок, отсутствие Dock, корректный выход.
  `output/balance-feedback-rc13-packaged/results.json`.
  На стенде текущий остаток изменён отдельным запросом на 90 г, устаревшее
  сохранение 80,01 г отклонено; после нового подтверждения сохранено 80,01 г.
  Исторические проводки 55 205 мг не изменились.
