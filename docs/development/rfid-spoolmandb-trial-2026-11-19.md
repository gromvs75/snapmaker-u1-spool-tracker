# RFID: установка, независимый откат и SpoolmanDB

19 ноября 2026 года. Работы выполнены в `output/rfid-bambu-2.1`. Реальный U1 не использовался. Новые приложения для Mac/Windows не собирались; ранее выданная 2.1.0rc1 этих изменений не содержит.

## Реализовано

`scripts/rfid_u1_trial.py` работает с офлайн-копией реальной структуры U1 2.1.0.157. План связан с драйвером, модулем и всем разобранным деревом include. Перед активацией сохраняются исходный конфиг, журнал установки и независимая копия инструмента. Активация записывается последней. OFF и откат не импортируют RFID и не используют API Klipper. Повторный OFF/откат безопасен; поздние изменения калибровки сохраняются. Предусмотрены отказы при устаревшем плане, чужом include, ссылках и уже существующем wildcard, который загрузил бы модуль дважды.

Выбран временный режим без `.debug`, init-правок и управления службами. При смоделированной штатной очистке системного слоя модуль и активирующий cfg исчезают вместе; точный необязательный include не блокирует запуск. Существующий `.debug` отклоняется. Это подготовка первого испытания; постоянный автозапуск и физическая установка не объявляются готовыми. CLI намеренно отвергает живой корень `/`.

`src/tracker_spoolmandb.py` использует включённый в исходники снимок 10 058 изделий. Сопоставление выполняется локально по бренду, материалу, точным цветам, известным диаметру/массе и при наличии точному названию. UID не используется как код изделия. Единственное совпадение предлагает параметры в существующей форме подтверждения; несколько совпадений оставляют ручной ввод. Каталог не меняет UID, не объединяет физические катушки, не подставляет остаток. При отсутствии/повреждении каталога регистрация с ручными параметрами и возврат известной катушки остаются доступны.

Источник: https://donkie.github.io/SpoolmanDB/filaments.json. Лицензия MIT включена в `src/tracker_spoolmandb_data/LICENSE`. SHA-256 исходного JSON: `5f34894187ab18c77b9a591c2f449fcee555cebb11956668aed7c5f63fc7461f`. Ревизия нормализованного снимка: `be5bb206796be254235b90e9b58e2a842e39298a9861106bdfbb8c91787dbe98`. Обновление выполняется явно скриптом `scripts/build_spoolmandb.py`; скрытой загрузки из сети в приложении нет. Спецификация упаковки включает данные каталога и лицензию в будущие сборки.

## Проверки

- **297 тестов прошли**, ошибок и пропусков нет: все девять форматов, подтверждение/вторая метка, каталог, аварийное отключение, установка/откат, UI регистрации, старые резервные копии и история. Отчёт: `output/rfid-spoolmandb-final-v2.xml`.
- **Финальный ZIP установлен через собственный CLI** на семи временных деревьях U1. Исходная распакованная копия затем удалена. Нормальный запуск, отказ API, синтаксическая ошибка, отсутствие модуля, неверный конфиг, отсутствие Klippy и очистка overlay. В каждом случае OFF выполнен из установленной копии; затем два настоящих запуска Klippy в `ready`, без RFID и с сохранением девяти точек mesh. Итого 14 запусков после OFF. Откат повторён дважды. `output/u1-trial-packaged-final/results.json`.
- Полный сценарий: синтетический Generic JSON NDEF с параметрами реального изделия SpoolmanDB → штатный драйвер через имитацию радиообмена → настоящий Klippy → форма в Chromium → официальный Spoolman 0.27.1 на loopback. Каталог предложил Bambu Lab Alpine Green Sparkle, плотность 1,26; пользовательское подтверждение задало 840,123 г. Один расход 20 г оставил 820,123 г. Привязка второй метки, перезапуск и четыре возврата сохранили одну катушку и остаток. Фактическое восстановление резервной копии сохранило остаток и происхождение параметров, подключения остались выключены. OFF/откат также завершились успешно. `output/spoolmandb-live-4/results.json` и снимки формы рядом.

Последний сценарий не доказывает, что заводская Bambu-метка использует Generic NDEF: это явно синтетический носитель для проверки интеграции каталога. Заводской Bambu-декодер покрыт отдельными регрессионными тестами. Радио, SPI/GPIO/MCU и печать имитировались. Новые изменения не проходили проверку в нативном Windows GUI; браузерная проверка её не заменяет.

В журнале полного сценария есть ошибки поздних фоновых запросов тестовой страницы во время завершения стенда, когда временный Klippy уже закрыт. Проверки подтверждения, списания, повторных установок и восстановления завершились до его остановки; это не свидетельство контакта с принтером.

## Сообщение о зависании Mac

У пользовательского процесса 2.1.0rc1 сохранён нативный снимок потоков и прочитан журнал. По сообщению пользователя кнопки импорта и проверки соединения оставались неактивными; после перезапуска работа восстановилась. Процесс завершён отдельно, база и настройки диагностикой не изменялись. Позднее работающий экземпляр пользователя не трогали.

Причина не доказана и исправление не заявляется. Предыдущая проверка импорта через API не покрывала выбор файла. Временный нативный диагностический прогон также не завершил последовательность выбора/выхода; сохранены потоки, процесс стенда остановлен. `dev/labs/uid_unified_bench/native_actions_macos.py` — ограниченный по времени диагностический сценарий, не успешный тест. Диагностика пользовательского зависания: `../mac-hang-2026-11-19/` относительно корня рабочего checkout; она не включена в пакет и не опубликована.
