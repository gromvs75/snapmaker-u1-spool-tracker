# Установка и откат RFID-модуля: стендовый пакет

Статус: **кандидат для офлайн-репетиции, не разрешение на установку на реальный U1**.
Этот пакет не подключается по SSH, не управляет службами, не запускает сканирование
и не меняет файл штатного драйвера. Запись разрешена только в явно маркированный
симулятор. Не создавайте такой маркер на реальном принтере для обхода ограничения.

**Дополнение 17.11.2026:** на исследованном штатном U1 2.1.0.157 системный слой
с extra очищается при загрузке, а пользовательский конфиг сохраняется. Простое
копирование файлов может оставить `[tracker_uid]` без Python-модуля и остановить
загрузку Klipper. Это воспроизведено на двух процессных стендах. Не включайте
`/oem/.debug` по этой инструкции: он сохраняет весь системный слой. Физическая
установка пока не подготовлена.
[Исследование загрузки и отката](../development/rfid-boot-lifecycle-2026-11-17.md).

Для ручных назначений модуль не требуется. Для RFID нужны сам `tracker_uid.py`,
его конфигурация и загрузка модулем Klipper. Одной правки конфига недостаточно.
Новая прошивка в рамках этого способа не прошивается: наблюдатель подключается
к штатному драйверу в памяти и сохраняет передачу его результатов штатному коду.

## Совместимость

Проверяется точный SHA-256 файла `fm175xx_reader.py`, а не название прошивки:

| Снимок драйвера | SHA-256 |
| --- | --- |
| 1.3.0.168 | `c118a0ff0077d789a558f738bead5cf8e10e28a0a57bb693ba47212303c6ece6` |
| 2.0.0.205 | `68ec97fd4dab74a1fb3690f6f2c4e889abac1c2dc9eedaebb43dab2657ddd392` |
| 2.1.0.157 | `ce7363f8b512e5474d18bd57cdf0660e6e2df57dc256e22f743b3b28c1b70be8` |

Это совместимость с закреплённым тестовым корпусом исходников, не подтверждение
совместимости фактического принтера пользователя. Другой хеш, включая изменённый
совместимый файл, отклоняется без режима `force`. При загрузке сам модуль дополнительно
проверяет методы драйвера в памяти и отказывается вмешиваться при чужих обёртках.
Неизвестный драйвер нельзя «поддержать», просто добавив его хеш в список.

## Состав и последовательность

Пакет содержит инструмент на стандартной библиотеке Python 3.9+ для POSIX,
модуль, инструкции RU/EN и `manifest.json` с хешами файлов и исходным коммитом.
Сверьте SHA-256 архива с полученным отчётом. Манифест обнаруживает повреждение,
но не заменяет цифровую подпись или проверку происхождения пакета.

Стенд должен быть подготовлен отдельно; он содержит `klipper/klippy/extras/`,
`printer_data/config/printer.cfg` и служебный маркер симулятора. Не используйте
`sudo`. Симулятор обязан быть остановлен; файл `.klipper-running` блокирует запись.
Само отсутствие файла не доказывает остановку настоящей службы — поэтому
пакет не предназначен для самостоятельной установки на реальное устройство.

Пример для **уже подготовленного временного стенда**, из распакованного пакета:

```sh
python3 rfid_module_tool.py inspect --simulator-root /private/tmp/rfid-test/a
python3 rfid_module_tool.py plan --simulator-root /private/tmp/rfid-test/a > /private/tmp/rfid-plan.json
python3 rfid_module_tool.py install --simulator-root /private/tmp/rfid-test/a --plan /private/tmp/rfid-plan.json
python3 rfid_module_tool.py inspect --simulator-root /private/tmp/rfid-test/a
```

`inspect` и `plan` не меняют стенд. Просмотрите план: он должен затрагивать ровно
три файла — новый extra, новый `tracker_uid.cfg` и добавление include в `printer.cfg`.
План привязан к корню, хешу драйвера, содержимому модуля и дереву конфигурации.
После любого изменения подготовьте новый план. Существующая установка не
обновляется поверх: для другой сборки нужен проверенный откат, затем новый план.

Перед первой записью создаётся отдельная копия исходного плана/файлов в
`.tracker-uid-backups/<идентификатор>.json` (права 0600) и журнал транзакции.
Каждая установка сохраняет свою копию; последующие установки её не затирают.
Повтор той же установки не добавляет второй include. Неизвестная схема старого
журнала требует ручной проверки, а не автоматической конвертации или удаления.

Проверяются вложенные include, циклы, отсутствующие обязательные файлы, симлинки,
жёсткие ссылки и существующие объявления `[tracker_uid]`. Wildcard include,
который подхватит новый `tracker_uid.cfg`, блокируется, чтобы модуль не загрузился
дважды. Инструмент не переписывает структуру пользовательского конфига за него.

После установки управляющий процесс стенда запускает Klipper. Нужно проверить
в Moonraker `tracker_uid`: `schema_version=1`, `state=ready`, ожидаемую версию
драйвера, новый epoch и четыре канала. Затем наблюсти тестовую метку на правильной
головке и штатный callback драйвера. `inspect` проверяет файлы, а не это runtime
состояние. Для снятия модуля симулятор снова полностью останавливают.

## Откат и сбои

```sh
python3 rfid_module_tool.py rollback --simulator-root /private/tmp/rfid-test/a
```

Откат удаляет только файлы установленного модуля и его точный include-блок.
Посторонние поздние изменения `printer.cfg` сохраняются. Штатный драйвер не меняется,
даже если его обновили после установки. После удаления модуль исчезает только
после нового запуска Klipper; живые перехватчики в памяти не выгружаются на ходу.

При прерывании установки выполните откат. При прерывании самого отката повторите
эту же команду: сохранённый план отката позволяет продолжить с оставшихся файлов.
Перед любой записью проверяется весь набор файлов. Повреждённая копия/журнал,
изменённый чужим кодом модуль или конфликт параллельного редактирования — причина
остановиться. Не удаляйте журнал и не заменяйте конфиг старой копией вручную:
сохраните каталог для разбора. Если конфиг изменён ещё до добавления нашего блока,
инструмент может потребовать ручной разбор вместо догадки о происхождении правок.

После успешного отката оригинал резервной копии остаётся, журнал перенесён в
`.tracker-uid-last-rollback.json`. Запустите стенд и проверьте обычный статус печати,
отсутствие объекта `tracker_uid` и доступность ручного режима Tracker.

## Перед физическим этапом

Нужны отдельное разрешение пользователя, фактические пути/версия драйвера,
проверка остановки и восстановления службы, доступный откат без Tracker и
свободный принтер. Физическое чтение, антенны, реальные метки и последствия
обновления прошивки на U1 пока не подтверждены. Windows GUI этой работой
не проверяется; установочный инструмент запускается на POSIX-стенде.
