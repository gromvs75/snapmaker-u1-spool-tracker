# Минимальный RFID для штатной U1 — стендовый пакет 0.2.0

Назначение: читать UID совместимых меток для привязки катушек в Tracker.
Целевая штатная прошивка этого пакета: **2.1.0.157**. Пакет предназначен
для изолированного программного стенда; физическая установка не выполнялась.

## Что добавляется

Один Klipper extra `tracker_uid.py` наблюдает выбор метки штатным FM175xx.
Файл штатного драйвера не меняется. Модуль не отправляет дополнительных команд
радиочтения или записи, не меняет данные материала, калибровки и остатки катушек.
UID передаётся через `tracker_uid/status` и объект `tracker_uid`.
Неизвестный драйвер или конфликт существующих обработчиков оставляет модуль
недоступным. Отказ регистрации его API также не должен останавливать Klipper.

Читается идентификатор, а не содержимое OpenSpool. Для катушки без заводской
метки можно использовать совместимую пользовательскую NFC-метку; записывать
на неё данные материала для одной лишь привязки UID не требуется. Распознавание
материала самим принтером — отдельная возможность, которую этот модуль не добавляет.
На стенде радиоответы, GPIO/SPI и MCU моделируются; реальные метки не проверены.

Внешний загрузчик и инструмент отключения отделены от extra. Загрузчик использует
ранее подготовленную модель автозапуска с `.debug`. В ней `.debug` сохраняет весь
системный слой, а не только RFID. Это моделируемая политика, не команда включить
`.debug` на принтере. Пакет не содержит SSH, прошивальщика или управления реальными
службами. Не создавайте маркер симулятора на U1.

## Независимое отключение

В установленной копии стенда сохранён отдельный `disable-rfid.py`:

```sh
python3 -I /absolute/simulator/persistent/tracker-deployment/debug-loader-kit/disable-rfid.py \
  --simulator-root /absolute/simulator
```

Он использует только стандартную библиотеку Python. Ему не нужны работающие
Klipper, Moonraker, Tracker или импорт RFID-модуля. Проверив запись установки,
он блокирует будущую активацию и переносит включающий конфиг в `disabled-configs`.
Повреждённый модуль остаётся для диагностики. `printer.cfg`, сохранённые калибровки,
штатный драйвер и `.debug` не переписываются. Повторное отключение безопасно.

Отключение действует **на следующий запуск Klipper**. Оно не выгружает Python-код
из уже работающего процесса и не останавливает службу. Стенд сам завершает только
свой дочерний процесс и затем проверяет два запуска без модуля.

Конкурирующая операция загрузчика блокирует отключение; нужно повторить после её
завершения. Повреждённая запись владения, посторонний include или символьная ссылка
требуют разбора — инструмент не удаляет произвольные пользовательские файлы.
Повреждение самого загрузчика/системного Python — отдельный сценарий, не обещанный
этим способом отключения неисправного Klipper extra.

## Воспроизведение в репозитории

`dev/labs/uid_boot_bench/emergency_off_run.py` принимает `--archive`, `--klipper`,
`--driver`, `--dictionary`, `--output`. Нужны Python 3.11, зависимости Klippy,
локальная копия Klipper со стендовым C helper, штатный драйвер 2.1.0.157 и
синтетический MCU-словарь. Входные файлы копируются во временные каталоги.

Проверяются нормальное чтение UID, отказ API, синтаксическая ошибка модуля,
отсутствующий модуль, неверная настройка и завершение Klippy до создания API.
После OFF — два запуска, штатные callbacks, неизменная сетка калибровки и
ручной учёт без UID. Результаты записываются в JSON и журналы процессов.

Это подготовка RFID для Tracker 2.1.0. Сборки Tracker 2.0.0rc21 не изменяются.
