## Что проверено именно в EXE

EXE скопирован один в папку `Tracker EXE isolated` вне checkout; PYTHONPATH и
PYTHONHOME удалены. Запускали непосредственно EXE, не Python с исходниками.
Результат фиксирует `frozen: true`, путь EXE и каталог распаковки `_MEI90282`.
HTML включён внутрь упаковки; нативное окно загрузило интерфейс из локального HTTP.

17 проверок GUI с реальными Win32 кликами/перетаскиванием и DOM-проверками:

- Русские надписи; два обязательных подтверждения; отмена со сбросом согласия.
- Разблокировка на 15 минут; истечение на лабораторных часах; запрет переноса.
- Повтор запроса без продления дедлайна; disconnect/reconnect.
- Повторное разрешение «до назначения», подтверждение и завершение окна.
- Drag U1_1 → U1_2, заблокированная занятая головка, подтверждение переноса.
- Повтор переноса сохраняет остаток; завершённое окно больше не блокируется.

В GUI-фикстуре чёрная катушка перешла на U1_2/T0. Остатки **499702 и 299404 мг**,
дебетов **0**, постоянная квитанция разрешения **1**. Снимки диалога переноса и
обычного запуска EXE просмотрены; надписи и элементы управления видны.

Отдельный сценарий **внутри того же EXE**, без pytest/импорта внешних исходников,
создал новую синтетическую SQLite и провёл ненулевой расход через AccountingOwner,
MotionLifecycle и обработку истории двух принтеров:

- Два задания с одинаковым history ID на разных принтерах: два списания по **298 мг**.
- **22** повторных пакета истории, включая повтор после reopen SQLite: без нового списания.
- Новое прерванное задание разрешено вручную; поздний terminal и **6** пакетов

- Итог: **2 дебета, 596 мг всего, остатки 499702/499702 мг, 1 квитанция разрешения**.

Дополнительно внешний smoke-driver запустил EXE **без аргументов**, увидел обычное
нативное окно, закрыл его через WM_CLOSE и получил exit code 0. В новой тестовой
папке подтверждены возврат event loop, две катушки и отсутствие списаний.

## Изменения

- `packaging/TrackerUidGuiWindows.spec`: отдельная one-file windowed сборка,
  включение HTML и WebView2-зависимостей; стабильная упаковка не изменена.
- `dev/labs/uid_windows_bench/app.py`: обычный запуск и явный frozen-only CI режим.
- `run.py`: файловая динамическая загрузка фикстуры заменена пакетным импортом,
  чтобы она попадала в EXE; выходной каталог задаётся вне временной распаковки.
- `replay.py`: проверка ненулевого учёта и постоянной защиты от поздней истории.
- `normal_launch.py`: независимая проверка обычного запуска/закрытия.
- `.github/workflows/uid-windows-exe.yml`: сборка, изолированный запуск, проверка
  результата, SHA256 и выгрузка EXE только после успешных проверок.

Оба выполненных EXE workflow завершились успешно. Ошибок GUI/учёта в упакованном
приложении не выявлено. При подготовке тестовой фикстуры дополнены обязательные
logical_weights профиля расхода; до этого она корректно отклонялась моделью.
PyInstaller сообщил о двух отсутствующих необязательных таблицах pycparser;
они не помешали сборке, WebView2, GUI и всем проверенным операциям.
