## Обнаруженная ошибка и исправление

Первое реальное подключение упакованного клиента завершалось
`ModuleNotFoundError: No module named 'websocket'` в `UidClient.start`.
Предыдущая EXE-проверка с синтетическим Fleet не вызывала этот транспорт.

В Windows build зависимости добавлен `websocket-client==1.8.0`, а в spec —
явный hidden import `websocket`. Исправлены оба workflow сборки EXE и процессного
стенда. После пересборки EXE подключился к обоим Moonraker и прошёл весь сценарий.

В инфраструктуре также исправлены чтение SHA256SUMS как текста в PowerShell,
передача путей через `wsl --exec` и сохранение точных CRLF-байтов исходного
RFID-драйвера. Проверка SHA256 не отключалась. Драйвер не изменён, его hash:
`ce7363f8b512e5474d18bd57cdf0660e6e2df57dc256e22f743b3b28c1b70be8`.

## Ограничения

Это Windows Server + реальные Linux-процессы в WSL1, а не физические U1.
Windows 10/11, другие DPI, установщик, реальные RFID/MCU/подача не проверялись.
Moonraker в WSL1 пишет диагностический `KeyError: operstate` при чтении сетевой
информации; его код не патчили. HTTP/WebSocket/история и проверяемые операции
работали, управление системными службами через Moonraker не проверялось.

Реальный принтер, установленный Tracker и пользовательская база не открывались.
Изменения сохранены в отдельной тестовой ветке без merge в main и без релиза.
Прежние 144 регрессионных теста относятся к предыдущему этапу; здесь результат —
14 выполненных сквозных проверок нового процессного EXE-стенда.
