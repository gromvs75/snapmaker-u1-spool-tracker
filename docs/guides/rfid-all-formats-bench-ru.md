# RFID 0.5.0: все девять форматов набора material-tags
> Продолжение: [RFID 0.6 — публичные ключи Creality и встроенный CC0-словарь TigerTag](rfid-automatic-lookup-bench-ru.md). Ограничения 0.5 ниже описывают прежнюю версию.


Лабораторное расширение Tracker 2.1. Реальный U1, установленный Tracker и пользовательские
настройки не изменяются. Это backend и программный стенд; Windows GUI с этим кодом
**не проверен**, новый пользовательский EXE не собирался.

## Покрытие

| Формат | Материал и цвет | Дополнительные условия |
|---|---|---|
| Bambu Lab | Материал, RGB/двухцветный | Сохранён общий tray UID двух меток |
| QIDI | Подтверждённые коды PLA/PETG и четыре цвета | Остальные коды неизвестны; диаметр и масса задаются отдельно |
| Anycubic ACE | Текст материала, RGB | Подтверждённые версии 0x64/0x65, SKU до 11 символов |
| Creality CFS | Код материала, справочник распространённых ID, RGB | Нужны два AES-ключа; диаметр и плотность задаются отдельно |
| Elegoo | Материал в decimal-digit encoding, RGB | Проверен опубликованный заводской блок с выравниванием по страницам |
| TigerTag / Plus | RGB до трёх цветов; числовые коды бренда/материала/продукта | Текстовые названия требуют явно заданного справочника; принимается только тип Filament |
| Generic JSON/NDEF | Бренд, материал, RGB до пяти цветов | Только application/json без поля protocol |
| OpenTag3D | Материал, бренд, RGBA до четырёх цветов | Версии 0/1 и 2; неизвестные major версии отклоняются |
| OpenPrintTag | Названия материала/бренда, RGB(A) до пяти цветов | Только payload на ISO14443A Type 2; заводская ISO15693-метка Prusa недоступна этому reader |

Это девять форматов опубликованного набора Bespok3d, а не обещание чтения любых
катушек любого производителя. Generic JSON не подменяет отдельный протокол OpenSpool:
JSON с `protocol` оставляется без метаданных до отдельной реализации этого протокола.

READ/AUTH идут через неизменённый утверждённый FM175xx. Creality использует AUTH B,
Bambu/QIDI — AUTH A. Type 2 читается блоками по четыре страницы, с проверкой UID,
границ и полноты. Никаких команд WRITE, URL-запросов из содержимого метки или изменения
штатного Snapmaker payload нет. У TigerTag учитывается единица массы (mg/g/kg), объём и неизвестные единицы не
выдаются за граммы. Тип Resin отклоняется. Неизвестный цвет не заменяется белым. Неоднозначный
payload нескольких поддерживаемых форматов не принимается.

## Катушка, две метки и остаток

Кроме Bambu, автоматическое объединение по полю метки здесь не применяется. У TigerTag
сохраняются timestamp/twin ID и номер/количество меток: это подсказка пары, но
32-битный timestamp не принят за глобально уникальный ID катушки. Идентичность:
`<format>:chip:<UID>`. Сходство материала, цвета, имени или SKU не объединяет катушки.
Первая новая катушка требует включения идентичности в `confirmed_new_tags`. Вторая
метка явно привязывается к существующей катушке при свежем сканировании и простое:

```python
ticket = owner.call('rfid_prepare', printer_id, channel)
owner.call('rfid_pair', ticket, existing_spool_id, confirmed=True)
```

После привязки повторные установки обеих меток и перезапуск восстанавливают запись
и остаток. Алиасы входят в backup; восстановление backup выключает автоматизацию.
Уже созданные катушки не сливаются. Нельзя привязкой скрыть неоднозначный POST.

Номинальная масса на метке — масса при изготовлении, **не текущий остаток**.
`remaining_weight`, `spool_id`, URL и похожие поля метки не управляют учётом.
Новая использованная катушка требует `new_spools: hold` и явного `initial_balances`.
У известной катушки берётся остаток Spoolman/Tracker; номинал не применяется повторно.
Списание идёт через ledger и Sender, неоднозначная доставка автоматически не повторяется.
Как ранее, допускается один автоматический регистратор Tracker на Spoolman.

## Настройки только подготовленного симулятора

```ini
[tracker_uid]
bambu_read_enabled: True
qidi_read_enabled: True
anycubic_read_enabled: True
creality_read_enabled: True
elegoo_read_enabled: True
tigertag_read_enabled: True
generic_ndef_read_enabled: True
opentag_read_enabled: True
openprinttag_read_enabled: True
```

Все дополнительные декодеры по умолчанию выключены. Creality читает опции
`creality_master_key` и `creality_payload_key`: по 32 hex-символа. В пакет ключи
производителя не включены. Отсутствующие/неверные ключи оставляют UID без метаданных.
Тестовые значения из `all_tag_fixtures.py` действуют только для синтетических карт.
Ошибки метаданных не меняют результат штатного callback.

Настройки `rfid` Tracker сохраняют `enabled`, `allow_create`, `send_usage`,
`new_spools`, `initial_balances`, `densities`, `diameters`, `nominal_weights`,
`confirmed_new_tags`. Добавлены `material_names` и `manufacturer_names`: словари
по **точному `material_id` из чтения** для неизвестного материала/бренда.
Название материала не перезаписывает уже распознанный материал. Название производителя
может быть явно уточнено. Неизвестный цвет по-прежнему блокирует автосоздание.

Например, для синтетического TigerTag из стенда:

```json
{
  "material_names": {"tigertag:01C8:0141:0000007B": "PLA"},
  "manufacturer_names": {"tigertag:01C8:0141:0000007B": "Bench filament"}
}
```

Это демонстрационные коды, **не таблица настоящих TigerTag**. GPL-справочники TigerTag
и чужой код не встроены. Сетевого автоматического справочника пока нет. Плотность,
диаметр и масса задаются для известного изделия, например после сверки со SpoolmanDB;
одного семейства PLA недостаточно для выбора плотности всех его разновидностей.
У Creality неизвестный ID тоже можно явно сопоставить через `material_names`.

## Стенд и независимое отключение

`dev/labs/uid_live_bench/all_formats_run.py` принимает `--archive`, `--klipper`,
`--driver`, `--dictionary`, `--spoolman`, `--spoolman-python`, `--research`, `--output`.
Работают настоящие Klippy и официальный Spoolman 0.27.1 на loopback/Unix socket,
с временными базами. RF, SPI/GPIO, MCU и печать имитируются. Внешняя синхронизация
Spoolman выключена. Публичные дампы должны находиться в исследовательском каталоге
и соответствовать manifest SHA256; они не входят в дистрибутив.

Creality, TigerTag, JSON и OpenTag3D проверяются синтетическими данными по формату.
Дополнительно читаются публичные заводские страницы Elegoo и Prusament CBOR,
перенесённый на синтетический Type 2 носитель. Это не проверка антенны/физических меток.

Отключение не требует работоспособного Klipper, Moonraker или импорта extra:

```sh
python3 -I /absolute/simulator/persistent/tracker-deployment/debug-loader-kit/disable-rfid.py \
  --simulator-root /absolute/simulator
```

Действует при следующем запуске. Не создавайте маркер симулятора на реальном U1.
Загрузчик при новой активации пересоздаёт cfg с выключенными декодерами: настройки
для воспроизведения вносит стенд после активации.
