# Technical notes for v1.0.1

The app has a tray process, one native pywebview window backed by a `127.0.0.1:8765` HTTP server, and a separate Orca post-processing process. Both share `spools_u1.json` in the per-user application data directory. The tray uses pystray `run_detached` with the same macOS `NSApplication`; pywebview owns the main GUI loop. Window close hides it, tray Quit destroys it and stops the monitor/server/icon. The tray command reliably reopens it. The embedded page polls `/api/data` every 2.5 seconds, updates live state in place, and protects focused/dirty form values. A browser can load localhost for troubleshooting, but native backup dialogs are unavailable there.

`storage.py` uses `filelock` on a stable lock file across threads/processes, reads under the lock, validates internal schema version 2, writes a temporary file, fsyncs, and atomically replaces the database. Schema 0 and 1 databases migrate on read. A damaged database is preserved and copied into `backups/`; no silent reset occurs.

`gcode.py` reads the file tail first, then streams a fallback if metadata is not near the end. It requires a valid per-tool `; filament used [g] = ...` line. `preflight.py` compares each active tool's requirement plus reserve with its assigned spool. The hook returns zero for OK or explicit Proceed Anyway, nonzero for Cancel, parse failure, or storage error. An allowed preflight stores a planned job with output filename, SHA-256 and size, four per-tool grams, four captured spool IDs, printer config, time and status. It never changes G-code or subtracts inventory on export.

The optional monitor polls stock Moonraker `/printer/objects/query?webhooks&print_stats` and `/server/history/list`. For a candidate history job it checks `/server/files/metadata` and hashes the read-only `/server/files/gcodes/<filename>` download. It requires matching basename, SHA-256, byte size, configured printer and preflight time. The history `job_id` plus `start_time` and printer form a persistent run key. `in_progress` marks active; `completed` debits captured spool IDs once in the same locked transaction as marking the run committed. Cancelled/error jobs do not debit the planned total. Unverifiable or ambiguous jobs need manual review. The monitor can resume from history after restart; it makes no cloud requests.

JSON POST requests require an appropriate host, same origin when provided, `application/json`, and at most 64 KiB. User input is rendered with DOM text nodes. The tray menu refreshes after database changes. A second launch does not create another server/tray; it can restore a minimized window, but the tray command is the reliable reopen path after X.

`backup.py` defines a separate portable format: `backup_format: SnapmakerSpoolTracker`, `backup_version: 1`, app version, ISO-8601 export time, and `data`. `data` holds internal schema version, language, reserve, spools, slots, printer config, last preflight, plans, and runs; it omits live `monitor`. Export reads a validated locked snapshot without rewriting the database, then atomically writes UTF-8 JSON to a native Save-dialog path outside the data directory. Import uses a native Open dialog plus confirmation, caps input at 10 MiB, checks the envelope and exact durable keys, and validates through `validate_db`. Under the same store lock, it saves the previous database to `backups/pre-import-*.json` before atomically replacing it. Invalid imports do not replace data. Monitor state is reset to disconnected when enabled or disabled otherwise and the normal poll resumes; UI/tray update without restart. Raw legacy DB import is deliberately unsupported by this UI. Internal backups are not protection from uninstall cleaners that remove the entire data directory; users must export a portable file elsewhere.

For user setup, see [README](README.md), [English manual](MANUAL_EN.md), and [Russian manual](MANUAL_RU.md). CI runs tests and PyInstaller builds a Windows `.exe` (Edge WebView2 Runtime required for the GUI) and unsigned macOS `.app` wrapped in a ZIP. `dev/` and fixtures are not packaged. The macOS packaged app, real Orca hook, and Fake U1 simulator have been exercised; Windows GUI and physical U1 hardware still require manual validation before a release decision.

Material mismatch detection is deferred because the current parser has no verified stable per-tool material metadata. Add it only after capturing representative Snapmaker Orca output and testing the mapping to T0–T3.
