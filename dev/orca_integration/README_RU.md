# Snorca U1: интеграционный стенд v1.2-alpha

**Только offline. Не готовая защита реальной отправки.**

`snorca.patch` добавляет `TrackerU1Offline.hpp` и перехватывает ветку U1 в
`Plater::send_gcode_legacy` после выбора Send/Print, перед записью настройки
`open_device_tab_post_upload`, созданием WebPreprintDialog и передачей контекста
шлюзу. На любом результате выполняется return. Успех означает успешный тест,
а не отправку; в GUI предусмотрено явное сообщение «Nothing was sent».
Другие пути, например команды из вкладки Device, этим патчем не защищены.
Поэтому даже пропатченную сборку нельзя подключать к реальным устройствам
в рамках этих испытаний.

## Что входит

- `snorca.patch`: патч к официальному Plater.cpp тега v2.4.1 и новый header.
- `source_pin.json`: URL и SHA-256 исходного файла, против которого проверен патч.
- `TrackerU1Offline.hpp`: тот же C++-мост отдельно для компиляции стенда.
- `bridge_harness.cpp`: вызывает этот header без GUI и шлюза.
- `offline_runner.py`: вызывает строгую проверку через TestAdapter, записывает
  отчёт и только при разрешении возвращает точный маркер протокола.
- `tests/test_orca_offline_integration.py`: испытания C++/Python цепочки,
  применимости патча и изоляции ОС.

Мост запускает Python через posix_spawn с argv, без shell; обязательны абсолютные
пути из переменных окружения. Результат принимается только при exit 0 и точном
маркере `TRACKER_U1_OFFLINE_ALLOWED_V1`. Есть внешнее ограничение времени (5 секунд
по умолчанию), предел stdout, отдельная группа процесса и завершение группы при
выходе. Внутренний timeout проверки задаётся в тестовом контексте (2 секунды по
умолчанию). Windows пока закрыт отказом, реализация процесса — macOS/Linux;
скомпилирована и испытана macOS-версия.

Это синхронный экспериментальный вызов: в GUI возможна задержка до timeout.
Для production потребуется асинхронное выполнение с блокировкой повторного
действия и отменой. Прямой вызов из многопоточного приложения использует
posix_spawn, не fork с исполнением C++ в дочернем процессе.

## Изолированная сборка исходников

Не менять `/Applications/Snapmaker Orca.app`. В отдельном checkout нужного тега:

```sh
git apply --check /absolute/path/dev/orca_integration/snorca.patch
```

Затем `git apply` того же файла. Патч уже включает header: дополнительно копировать
его не нужно. Сборка всего приложения требует штатных зависимостей Snorca.

Перед запуском отдельной тестовой сборки задаются:

- `TRACKER_U1_TEST_PYTHON`: абсолютный путь к Python;
- `TRACKER_U1_TEST_RUNNER`: абсолютный путь к offline_runner.py;
- `TRACKER_U1_TEST_CONTEXT`: путь к JSON ниже;
- `TRACKER_U1_TEST_REPORT`: путь для одноразового тестового отчёта.

```json
{
  "offline_test": true,
  "device_id": "FAKE-U1",
  "mapping": [0, 1, 2, 3],
  "inventory_path": "/tmp/isolated-test/inventory.json",
  "checker_timeout": 2
}
```

Контекст представляет окончательный выбор тестового устройства/mapping; это
не чтение реального выбора из Flutter. `checker_command` допускается только
в доверенных тестах для инъекции ошибок. Контекст, runner, interpreter и отчёт —
части доверенного стенда, не интерфейс для сторонних web-запросов.

## Воспроизведение испытаний без GUI

Из корня Tracker, после загрузки закреплённого Plater.cpp в отдельный каталог:

```sh
TRACKER_TEST_PLATER_SOURCE=/tmp/tracker-orca-presend/source/Plater.cpp \
TRACKER_ASSERT_OS_ISOLATION=1 PYTHONDONTWRITEBYTECODE=1 \
/usr/bin/sandbox-exec \
-p '(version 1)(allow default)(deny network*)(deny file-write* (subpath "/Users/viktor"))' \
/tmp/tracker-presend-test-env/bin/python -m pytest -q -p no:cacheprovider \
tests/test_orca_offline_integration.py tests/test_presend.py \
tests/test_material_guard.py tests/test_tool_mapping.py
```

Профиль указан для этой машины; на другой машине заменить домашний путь.
Тесты компилируют мост и создают inventory/G-code/context/report в временных
каталогах. Сеть запрещена также дочерним процессам. Специальный тест проверяет
отказ bind на loopback и отказ создания временного файла в репозитории под
запрещённым домашним каталогом. Он не пробует писать пользовательские настройки.

Без переменных проверки исходника/OS соответствующие тесты явно пропускаются;
для полной проверки стенда обе переменные обязательны. Если нет C++ компилятора,
интеграционные тесты компиляции пропускаются, что не считается проверенным мостом.

## Проверенное и непроверенное

Проверяются оба action: Send и Print; allow, нехватка, crash, timeout, неверный
JSON, лишний mapping, отсутствие offline-флага. Отдельно проверяются отсутствие
конфигурации/runner, зависание runner, ложный маркер, превышение stdout и аргументы
с shell-символами. При отказе checker счётчики upload/start равны нулю. При сбое
самого моста настоящий offline endpoint вообще не достигается (отчёта нет).

Патч применён в тестовую копию исходника, header собран с
`-std=c++17 -Wall -Wextra -Werror`. Структурный тест проверяет return до шлюза,
изменения настройки и открытия WebPreprintDialog. Это не компиляция всего
Plater.cpp и не GUI-тест. Полное приложение не собрано: локально отсутствуют
CMake/Ninja и подготовленные GUI-зависимости. Установленная Snorca не запускалась
и не изменялась в ходе этих интеграционных испытаний.

Для настоящей интеграции ещё нужны окончательный выбор device/mapping из шлюза,
неизменяемое задание, атомарное резервирование инвентаря и обязательный gate всех
поддерживаемых upload/start маршрутов. Передача раннего allow штатному шлюзу
вместо текущего return недопустима: это снова откроет непроверенный путь.
