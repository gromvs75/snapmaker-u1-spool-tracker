# Две метки и общий ID физической катушки

Статус на 19.11.2026: проверено на программном стенде, реальный U1 не использовался.
Новая поддержка OpenPrintTag входит в кандидат 2.1.0rc2 и модуль
`0.8.0-roll-identity-bench`. В ранее выданные Mac/Windows 2.1.0rc1 она не входит.

UID — идентификатор чипа. Общий ID катушки — отдельное поле в содержимом метки.
Материал, цвет, артикул и ID товара могут совпадать у множества разных катушек.

| Формат | Что известно об общем ID | Поведение Tracker |
|---|---|---|
| Bambu Lab | 16 байт блока 9, Tray UID / spool ID; одинаковый у двух сторон | Автоматическая связь разных UID уже была реализована и повторно проверена на публичных дампах |
| OpenPrintTag | Явный `instance_uuid`, ключ 0 основной CBOR-карты: конкретный экземпляр упаковки | Добавлена автоматическая связь при одинаковом валидном UUID; ключи товара/материала/бренда не используются |
| TigerTag | `Twin Tag ID & Timestamp`, секунды с 2000 года; также индекс/количество меток | Поле прочитано, но остаётся ручное подтверждение: одинаковая секунда и продукт не дают гарантии уникальности между производственными линиями/записывающими устройствами |
| OpenTag3D | `Serial Number / Batch ID` может обозначать целую партию | Ручная привязка второй метки |
| QIDI | В изученном декодере три кода: материал, цвет, производитель | Ручная привязка второй метки |
| Anycubic ACE | Декодируются SKU и свойства материала; подтверждённого ID отдельной катушки нет | Ручная привязка второй метки |
| Creality CFS | Есть предполагаемое поле serial, но его смысл не подтверждён декодером | Ручная привязка второй метки |
| Elegoo | Декодируются свойства материала; общий уникальный ID катушки не подтверждён | Ручная привязка второй метки |
| Generic JSON/NDEF | `spool_id`/`id` может означать запись в сторонней базе; общего стандарта уникального ID физической катушки нет | Не импортируется как ID Spoolman и не объединяет катушки автоматически |

Это вывод об изученных форматах и декодерах, а не утверждение, что у производителя
никогда не бывает других меток или иных полей.

## Как проходит автоматическая привязка

1. Первая метка новой катушки: подтвердите материал, цвет, параметры и фактический
   остаток. В Tracker и Spoolman создаётся одна запись.
2. После снятия и переворота катушки считывается другой UID. Если общий ID совпадает,
   свойства согласованы и нет конфликта размещения, Tracker автоматически добавляет
   UID к существующей катушке. Второе подтверждение и новая запись не нужны.
3. Остаток берётся из учёта. Незавершённое локальное списание сохраняется и не
   перезаписывается старым остатком сервера. Номинальные 1000 г с метки не возвращаются
   вместо измеренного/учтённого остатка. Запись на метки не выполняется.

Если общего ID нет, используйте существующее действие привязки второй метки.
Если ID изменился, свойства не совпали, UID уже принадлежит другой катушке либо
катушка одновременно видна на двух головках, автоматическая привязка блокируется.
Уже созданные отдельные записи не сливаются автоматически.

Для OpenPrintTag поддерживается именно **явно записанный** `instance_uuid`.
При его отсутствии вычисляемый по UID чипа идентификатор не связывает разные чипы.
`package_uuid` — ID изделия, несмотря на похожее название, а не отдельной катушки.
Нулевой, полностью FF, неправильной длины или типа UUID отклоняется.

При обновлении старой регистрации OpenPrintTag сначала повторно считайте уже
привязанный UID: Tracker сохранит обнаруженный общий UUID без смены записи Spoolman
и её остатка. Раньше это поле не сохранялось, поэтому из старой базы восстановить
его без чтения метки невозможно. Резервная копия новой версии сохраняет связь.

Две физически разные катушки с намеренно скопированным одинаковым ID и содержимым
невозможно различить только по этому общему ID. Поэтому он должен обозначать
конкретную катушку, а не шаблон, записанный на все купленные NFC-наклейки.

OpenPrintTag здесь проверен как payload на Type 2 носителе. Это не добавляет U1
поддержку ISO15693 заводских меток Prusa. Проверка радиоканала на железе ещё предстоит.

## Результат стенда

Для Bambu использованы два опубликованных дампа с разными UID и одинаковым блоком 9;
для OpenPrintTag — синтетическая пара по спецификации. Настоящие процессы Klippy и
Spoolman 0.27.1 работали с временными базами; радио, SPI/GPIO/MCU и печать имитировались.
Обе пары сохранили **820,123 г после расхода 20 г из 840,123 г**. Повторные установки,
перезапуск и восстановление резервной копии проверены. Две другие катушки того же
материала и цвета с другими ID остались отдельными. 400 команд AUTH/READ, 0 WRITE.
После OFF Klippy запустился без модуля, откат выполнен.
