# 2.0.0rc5 — история и ручная корректировка

Контрольная точка: `checkpoint/2.0-before-history-review-20261116` (`5694571`). Ветка: `integrate/2.0-legacy-backup-dock`. Исходная регрессия rc4: 888 passed, 3 skipped.

## Причины и изменения

- Кнопки диалога добавлялись подряд без контейнера с отступами. Теперь используется переносимая группа с промежутками 10 px, отдельным основным действием и нейтральными вторичными кнопками. Закрытие перенесено в заголовок справа.
- В очереди название, дата, сумма и большая синяя кнопка сливались в один абзац. Теперь это отдельные строки с компактной вторичной кнопкой справа; на узком экране блок переносится.
- Ручная форма была доступна через «Да — проверить списание». После `close` состояние становилось `resolved`; фронтенд скрывал все действия, backend также запрещал корректировку. При этом историческая строка не объясняла, что задание закрыли без списания. Это воспроизведённая причина в коде; состояние конкретной пользовательской записи не исследовалось, пользовательская база не открывалась.
- Теперь `resolved` без окончательной квитанции учёта можно явно проверить и вручную учесть позже. Отменённое задание с частичным учётом и без окончательной квитанции также поддерживает дополнительный ручной расход. Автоматически задание не возобновляется.
- Диалог показывает состояние и объясняет недоступность действий при продолжающемся наблюдении или завершённом учёте. В истории состояние `resolved` подписано «Закрыто без списания».
- Известные причины «невозможно исключить автозамену» и «разрыв во время паузы» локализованы. Добавленные тексты доступны на RU/EN/DE/UK/ES.

## Защиты

Окончательная квитанция/завершённый учёт запрещают повторное списание. Сохраняются проверка версии данных, идемпотентный ID запроса, проверка завершения печати, свежая проверка подключённого принтера, запрет занятых другим заданием катушек, ограничение остатка и блокировка неопределённых отправок Spoolman.

Поле задаёт **дополнительный**, а не суммарный расход. Для обычного частично учтённого задания предлагается только разница. При импортированной истории/замене катушки количество не подставляется автоматически: пользователь проверяет сохранённый план и вводит распределение. Корректировка уже окончательно учтённой записи, возврат филамента и произвольная привязка несвязанных катушек этим изменением не добавлены.
