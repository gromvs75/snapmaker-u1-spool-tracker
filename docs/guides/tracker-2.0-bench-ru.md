# Проверенная стендовая сборка Tracker 2.0

Эта сборка запускается отдельно от стабильной 1.3.3. Она не читает установленную
конфигурацию и не переносит пользовательскую базу автоматически.

## Запуск

Двойной щелчок по `.app` или `.exe` открывает GUI с **новой временной базой**.
Это удобно для осмотра интерфейса. Чтобы сохранять стендовые настройки и катушки
между запусками, укажите один и тот же отдельный каталог явно.

macOS, из каталога распакованной сборки:

```sh
./Tracker-2.0-Settings-Bench.app/Contents/MacOS/Tracker-2.0-Settings-Bench \
  --data /tmp/Tracker20ReadyBench --window \
  --allow-url http://127.0.0.1:18781 --allow-url http://127.0.0.1:18782
```

Windows PowerShell, из каталога распакованной сборки:

```powershell
.\Tracker-2.0-Settings-Bench.exe --data "$env:TEMP\Tracker20ReadyBench" --window `
  --allow-url http://127.0.0.1:18781 --allow-url http://127.0.0.1:18782
```

Адреса выше — процессные стенды, не реальные принтеры. Сами стенды запускаются
инструментами разработки, описанными в отчёте. Без запущенного стенда соединение
не установится. GUI не запускает Klipper/Moonraker за пользователя.
В изолированной сборке разрешённые адреса задаются аргументами `--allow-url`;
для тестового Spoolman отдельно нужен `--allow-spoolman-url`.

## Основной сценарий

1. В настройках добавьте постоянные ID, имена и разрешённые адреса двух стендов.
   Сохраните настройки, затем включите подключения.
2. Зарегистрируйте наблюдённые метки или подтвердите назначения катушек без меток.
   UID и остаток сохраняются при переносе; физическую установку подтверждает пользователь.
3. В истории смотрите источник и распределение расхода. «Учтено расчётно» означает
   оценку по истории/плану, а не взвешивание.
4. Если граница замены неизвестна, откройте «Сверить расход», введите расход каждой
   предложенной катушки (включая 0), основание и подтверждение. Сумма должна совпасть.
   Сохранённое решение не применяется повторно при потере ответа или повторе истории.
5. В настройках → «Отправки» отдельно разрешайте отправки Spoolman. Неопределённый
   ответ требует ручной сверки; автоматического повтора нет.
6. Для восстановления остановите подключения, выберите копию, проверьте целостность
   и подтвердите замену. Приложение сохраняет копию текущего состояния. После restore
   назначения требуют проверки, старые неопределённые отправки не уходят заново.

Закрытие окна оставляет приложение в трее. Полный выход — пункт «Выход».
Второй процесс с той же базой отклоняется. Повторный запуск без `--data` создаёт
другую временную базу и потому не является проверкой единственного экземпляра.

Ограничения и точное разделение автоматических/нативных проверок:
