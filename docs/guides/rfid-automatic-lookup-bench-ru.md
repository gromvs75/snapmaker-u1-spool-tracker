# RFID 0.6.0: автоматические Creality и TigerTag

Продолжение лабораторной версии 0.5. Реальный U1, установленный Tracker,
пользовательские базы и настройки не изменяются. Windows GUI с этим кодом
**не проверен**; это backend и пакет симулятора, не Windows EXE.

## Creality

При `creality_read_enabled: True` используются опубликованные общие ключи CFS:

- master: `713362755e74316e71665a2870662431`;
- payload: `484043466b526e7a404b4174424a7032`.

Источник — DnG-Crafts/K2-RFID, ревизия
`7101bac4499a76e64b39460b63a8c3f446e5c127`, `Arduino/ESP32/Spool_ID/src/AES/AES.cpp`.
Это публичные общие параметры протокола, не ключи пользователя или доступа к принтеру.
Их SHA256 совпадают с опубликованными контрольными хешами Bespok3d.

Копировать ключи в cfg больше не требуется. Для стендов остаются явные overrides:
`creality_master_key` и `creality_payload_key`. Если задан хотя бы один, нужны оба
корректных 16-байтных hex-ключа. Ошибочные, неполные или пустые overrides **не заменяются
автоматически** заводскими ключами: чтение остаётся UID-only. Неподходящие ключи,
ошибка AUTH или неполный payload тоже не дают выдуманных материала/цвета.

Материал определяется по известному Creality ID, цвет — из расшифрованного RGB.
Неизвестные material ID по-прежнему требуют сопоставления: ключи не заменяют
каталог разновидностей. Плотность и отсутствующий диаметр не угадываются.

## TigerTag

В Tracker встроен офлайн-словарь кодов из официального TigerTag registry, ревизия
`77e13b065df3232f4819cdf20c4c89d4cea2576e`. Он содержит 112 записей материала для
Filament и 160 записей бренда для Filament; из них 111 и 159 дают конкретное
автоматическое определение. Служебные `0xFFFF` (`None` и `Generic`) остаются неизвестными.
Записи других типов изделий не используются для определения филамента.

Официальный проект теперь явно лицензирует `database/*.json` как **CC0-1.0**.
Указанное в прежнем отчёте 0.5 ограничение про GPL больше не описывает актуальный
справочник. Встроены только ID и названия, без логотипов и чужого программного кода.

Чтение даёт коды материала/бренда/продукта и RGB(A). Tracker автоматически
подставляет названия при регистрации карточки и создании записи Spoolman.
Например, коды материала `38219` и бренда `35123` дают PLA / Bambu Lab.
Цвет всегда берётся из метки, не подменяется ближайшим цветом каталога.
Сетевых запросов к TigerTag при чтении нет; работа не зависит от доступности API.

Явные настройки `material_names` / `manufacturer_names` сохраняют приоритет.
Неизвестные ID не получают похожее название. Если материал или бренд не определён,
автосоздание удерживается до уточнения. Плотность не берётся автоматически из общего
семейства материала: требуется подтверждённая калибровка изделия, как в 0.5.

Сырые данные метки сохраняются отдельно; источник расшифровки названий записывается
в `lookup_sources` карточки. Словарь не меняет UID, идентичность катушки, цвет,
номинальную массу или остаток. Поэтому прежние привязки и вторая сторона не
разваливаются при появлении автоматических названий. Уже созданные карточки с
явными пользовательскими названиями автоматически не переименовываются.

## Учёт и проверка

Новая катушка всё ещё требует подтверждения `confirmed_new_tags`. Вторая метка
привязывается через `rfid_pair`; совпадение материала/цвета не объединяет разные
катушки. После привязки обе стороны автоматически восстанавливают прежний остаток.
Номинал не сбрасывает текущую массу, записи в NFC нет.

Стенд `dev/labs/uid_live_bench/all_formats_run.py --automatic` не задаёт ключей
Creality или ручных словарей названий TigerTag. Он использует штатный утверждённый
FM175xx, настоящий Klippy и официальный Spoolman 0.27.1, временные базы и loopback.
RF/SPI/GPIO/MCU и печать имитируются. Creality-карты синтетические, зашифрованные
публичными ключами; данные для проверки получены независимо через OpenSSL.
TigerTag — синтетическая карта с настоящими кодами официального справочника.
Это не аппаратная проверка заводской катушки.

Все read-флаги по умолчанию выключены. Независимый OFF остаётся прежним и не требует
работающего Klipper. [Полные настройки и OFF версии 0.5](rfid-all-formats-bench-ru.md).
[Источники, хеши и результаты 0.6](../development/rfid-automatic-lookup-2026-11-19.md).
