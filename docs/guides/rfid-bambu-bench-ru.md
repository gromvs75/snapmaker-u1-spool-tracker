# Bambu RFID 0.3.0 — программный стенд Tracker 2.1

Реализован путь: Bambu RFID → материал/цвет → катушка Spoolman → расход Tracker →
повторная установка с прежним остатком. Реальный U1 и установленные приложения не
использовались. Это экспериментальная ветка; готовые сборки 2.0.0rc21 не изменены.
Windows GUI с этим изменением **не проверен**. Пользовательского установщика 2.1 пока нет.

## Чтение и идентичность

Extra `tracker_uid.py` версии `0.3.0-bambu-bench` работает поверх проверенного
штатного FM175xx. Основной сквозной прогон использует драйвер U1 2.1.0.157.
Файл драйвера не патчится. Опция `bambu_read_enabled: True` добавляет ограниченное
чтение Bambu после неудачи штатного распознавания: AUTH A и READ, без WRITE.
При выключенной опции остаётся прежнее наблюдение UID.

Сначала штатный код получает свой исходный результат; Bambu-данные публикуются
отдельно в `tracker_uid.channels[channel].tag`. Они не подменяют штатный формат
Snapmaker и не меняют настройки температуры/материала самого принтера.
Ошибка чтения метаданных оставляет только UID, а не выдуманные свойства катушки.

У катушки может быть несколько чипов. Для Bambu общий 16-байтный tray UID из
блока 9 определяет катушку, а UID чипов становятся её алиасами. Число алиасов не
ограничено двумя. Материал и цвет не используются как идентификатор катушки.
Два одновременных назначения одной катушки блокируются, даже с разными чипами.
Для других брендов общий идентификатор ещё нужно подтвердить отдельно.

## Учёт

Spoolman хранит остаток; Tracker хранит привязку, локальный журнал расхода и очередь
отправки. Известная катушка не получает заново номинальную массу из RFID.
При незавершённой отправке локальный остаток сохраняется, чтобы ответ сервера
не затёр ещё не доставленный расход. После неоднозначного HTTP-ответа повторное
списание блокируется до сверки.

Создание записей разрешается отдельно. Перед каждым POST сохраняется намерение
в SQLite. После потери ответа повторный поиск может найти уже созданную запись;
если её нет, автоматический повтор POST запрещён. Идентичность записана отдельной
строкой комментария Spoolman `Tracker RFID bambu:<tray UID>`. Несколько совпадений
блокируют привязку. Архивная катушка не активируется автоматически.

Эта версия рассчитана на один процесс регистрации на общий Spoolman. Комментарий
Spoolman не является серверным уникальным ограничением: независимые профили,
одновременно создающие одну катушку, требуют отдельной координации. Уже заведённую
вручную катушку без этого маркера нельзя найти по одному цвету/названию; её связь
нужно указать явно. Новый GUI выбора такой связи здесь не добавлялся.

Плотность отсутствует на Bambu RFID. Она задаётся по конкретному коду материала
или точному имени разновидности. Например, проверенный каталог SpoolmanDB даёт
для PLA Basic 1,24, PLA Silk 1,32 и PETG Basic 1,25 г/см³. Общее имя PLA для такой
подстановки не используется. При импорте берутся параметры filament из Spoolman.

## Включение в тестовом профиле

По умолчанию новая функциональность выключена. На стенде модуль получает
`bambu_read_enabled: True` в активирующем cfg после запуска лабораторного загрузчика.
Прогон делает это сам. Это не инструкция изменения рабочего U1: следующий запуск
лабораторного загрузчика пересоздаёт cfg с безопасным значением по умолчанию.

Backend-настройка отдельного временного профиля через `AccountingOwner.save_settings`:

```json
{
  "spoolman_url": "http://127.0.0.1:<bench-port>",
  "spoolman_mode": "send",
  "rfid": {
    "enabled": true,
    "allow_create": true,
    "send_usage": true,
    "new_spools": "nominal",
    "densities": {"GFA00": 1.24, "GFA05": 1.32, "GFG00": 1.25}
  }
}
```

`new_spools: nominal` означает явное предположение «новые катушки полные».
Для ранее использованных катушек нужен `new_spools: hold` и точная начальная масса
в `initial_balances`, где ключ — `bambu:<tray UID>`. Номинальная масса не измеряет
остаток. `send_usage` разрешает автоматическую доставку только новых подтверждённых
списаний RFID-катушек. Восстановление резервной копии выключает RFID-автоматизацию.

Session запускает и останавливает RFID worker вместе с подключениями. Изменение
режима требует остановить подключения. HTTP выполняется вне SQLite-транзакции;
перед привязкой повторно проверяются наблюдение, соединение, задание и остаток.

## Воспроизведение и отключение

`dev/labs/uid_live_bench/bambu_run.py` принимает `--archive`, `--klipper`, `--driver`,
`--dictionary`, `--spoolman`, `--spoolman-python`, `--research`, `--output`.
Требуются подготовленные зависимости Klippy, официальный checkout Spoolman 0.27.1,
публичные дампы с manifest и синтетический MCU-словарь. Сервер запускается только
на loopback; все базы и конфигурации создаются во временном каталоге.

В архиве есть независимый `disable-rfid.py`. Для установленной копии **стенда**:

```sh
python3 -I /absolute/simulator/persistent/tracker-deployment/debug-loader-kit/disable-rfid.py \
  --simulator-root /absolute/simulator
```

OFF не импортирует Klipper или RFID-код и не требует их API. Он отключает следующий
запуск, сохраняя неисправный модуль для диагностики. Реальный принтер не обслуживается
этим инструментом. Подробности старого UID-пакета — в `UID-0.2.md` внутри архива.
