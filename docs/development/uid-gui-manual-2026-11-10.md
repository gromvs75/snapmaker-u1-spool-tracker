# GUI ручных назначений и переноса — 10 ноября 2026

Подключён отдельный стендовый экран Tracker 2.0 к рабочей SQLite-модели через
AccountingOwner. Это функциональный интерфейс: подтверждение и перенос меняют
назначения в тестовой БД, а не только отображение карточек. Установленный Tracker,
реальный принтер и пользовательские настройки/база не использовались.

## Реализованный сценарий

Карточка показывает имя катушки, наличие метки, принтер/головку, остаток и
состояние подтверждения. Для старого неподтверждённого назначения доступна кнопка
«Подтвердить», для свободной катушки — «Назначить», для назначенной — «Перенести».

Диалог подтверждения показывает конкретную катушку и место. Checkbox всегда
снят при открытии; без него сохранение недоступно. Перенос показывает исходное
место, остаток, выбор целевого принтера и головки и требует подтвердить физическое
снятие/установку. Занятые головки и недоступные принтеры нельзя выбрать. Отмена
ничего не пишет. Во время запроса кнопка блокируется от повторного нажатия.

Кнопки изменения активной катушки заблокированы; сервер повторно проверяет
активные задания и занятость головок независимо от браузера. Состояние экрана
периодически обновляется вне открытого диалога. Если назначение изменилось во
время открытого диалога, операция отклоняется по версии, показывается причина
и кнопка «Обновить данные»; автоматического повтора с новыми данными нет.

## Гарантии модели

Добавлен transfer_manual: проверка исходной версии, обеих сторон, UID-конфликтов,
активных резервов и запись нового места выполняются одной SQLite-транзакцией.
Не используется последовательность «сначала снять, потом попробовать назначить».
Ошибка назначения или SQLite не теряет исходное место. Остаток и spool_id при
переносе не меняются; операции расхода не вызываются.

Каждый перенос имеет request_id и сохранённый результат. Повтор того же запроса
возвращает квитанцию, даже если катушка уже в новом месте. Повтор request_id с
другими параметрами отклоняется. Подтверждение назначения также проверяет версию;
запрос из старого экрана не может молча заменить новое назначение.

Локальный HTTP bridge проверяет Host, Origin и случайный токен экземпляра.
Произвольные операции owner через HTTP не доступны: только чтение состояния,
подтверждение/назначение и перенос. Все записи идут через единственный SQLite-поток.

## Проверки

393 автоматических теста: прежние 383 плюс 10 проверок backend GUI. Проверены
атомарный перенос и повтор запроса, занятая головка, активное задание, offline,
устаревшая версия, конфликт UID на обеих сторонах, отсутствие подтверждения,
повтор подтверждения и откат при искусственном SQL-сбое.

12 браузерных проверок на реально запущенном localhost GUI с тестовой SQLite:

- checkbox не отмечен и submit недоступен до подтверждения;
- отмена сохраняет неподтверждённое назначение;
- подтверждение проходит через API/очередь в SQLite;
- перенос сбрасывает checkbox, сохраняет 500 г и меняет U1_1:T0 → U1_2:T2;
- новое место сохраняется после перезагрузки страницы;
- занятую T2 нельзя выбрать для другой катушки;
- POST без токена отклоняется;
- при ширине 640 px нет горизонтального переполнения;
- повтор переноса возвращает сохранённый результат;
- устаревший диалог показывает ошибку и сохраняет исходное назначение.

Скриншоты и выводы проверок находятся в output/uid-gui-bench/ и
output/uid-gui-*.png. Воспроизведение: dev/labs/uid_gui_bench/README.md.

Для UI выполнен быстрый поиск Lazyweb по desktop transfer dialogs. Для нового
экрана сервис вернул create-redirect; после реализации снят скриншот и отправлен
через upload на полный обзор читаемости подтверждения/переноса. Рекомендации
не меняют ограничения учёта и не разрешают физический перенос сами по себе.

## Ограничения

Это новый GUI-стенд с тем же HTML, пригодным для pywebview. Проверен браузерный
рендеринг и реальная тестовая модель; нативные Cocoa/Windows окна в этом этапе
не проверялись. Рабочее окно установленного Tracker не модифицировано и экран
не добавлялся в его меню. Стенд использует две симулированные fleet-записи;
реальные Klipper/Moonraker на этом этапе не запускались.

GUI переноса относится к ручным назначениям. Катушки с RFID сохраняют механизм
автоматического распознавания; ручное переопределение UID-конфликта не добавлено.
Перенос физически выполняет пользователь, интерфейс лишь подтверждает запись.
Активные задания с потерянной непрерывностью остаются заблокированными до
отдельного сценария разрешения review. Ничего не опубликовано.

Итоговый обзор Lazyweb готов без пропущенных вариантов:
https://www.lazyweb.com/report/lazyweb/d3a46696-55b7-4344-a101-7d10b2890783/?source=create

Стенд после проверки остановлен. В сохранённой тестовой БД — два подтверждённых
переноса, ноль списаний; оба остатка не изменились. Проверка:
output/uid-gui-bench/db-verification.json. Нативный Windows GUI не проверен.
