# Проверка пользовательского кандидата 2.0.0

Это кандидат, не стабильный релиз. Не заменяйте им установленную 1.3.3.

macOS: откройте `Snapmaker-Tracker-2.0-Candidate.app`. Обычный запуск сохраняет
данные в `~/Library/Application Support/Snapmaker Tracker 2.0` и не использует
базу 1.3.3. Принтеры после каждого запуска отключены. Подключение выполняется
явно в **Настройки → Принтер**; ID связывает принтер с прежней историей.

**Катушки → Библиотека** — поиск, добавление, просмотр назначения и остатка.
**Головки T0–T3** — назначения, регистрация неизвестных UID и перенос.
Верхний выбор принтера задаёт контекст обзора; библиотека остаётся общей,
а назначения подписаны именем принтера и головкой.

В rc17 ручные назначения работают при подключённом принтере без UID-модуля.
Подтверждение расположения не меняет остаток. После разрыва связи оно требует
повторной проверки. [Ручной режим, состояния RFID и требования к модулю](manual-and-rfid-2.0-ru.md).

**История → Раскрыть задание** показывает сохранённый план без принтера и
слайсера. Для неподтверждённого задания выберите: перейти к списанию, отложить
или закрыть без списания. Дополнительный расход можно исправить. После замены
распределите его между конкретными катушками; прежний остаток не означает,
что катушка израсходована полностью. Не подтверждайте завершение, пока печать
может продолжаться.

**Настройки → Spoolman → Передача расхода** — явное разрешение и отправка.
Неопределённые операции требуют ручной сверки с внешним журналом. Текущий
остаток сам по себе не доказывает, был ли расход уже отправлен. После рестарта
открытые операции консервативно переводятся на сверку.

**Настройки → Резервная копия** — сохраните копию. Для восстановления остановите
подключения, выберите файл, проверьте целостность и подтвердите замену базы.
Перед заменой сохраняется копия текущего состояния. Старые незавершённые
отправки не возобновляются автоматически.

**Обзор** раздельно показывает план текущей печати и прогноз обнаруженной
нарезки. Стол для просмотра не означает выбранный стол в слайсере.
Изменяющиеся/удалённые файлы не показываются как актуальная готовая нарезка.
Папка наблюдения задаётся в **Настройки → Учёт**.

**Номера столов Snorca (rc16 и новее):** для надёжного определения номера
добавьте `; TRACKER_BED_V1 = {plate_number}` первой строкой G-code начала
печати в отдельном профиле принтера Snorca. Сохраните профиль, **выберите его
в текущем проекте** и заново нарежьте. Без этой настройки номер может быть
неизвестен, хотя сам прогноз расхода доступен. Экспорт и отправка на принтер
не нужны. [Пошаговая инструкция и диагностика](snorca-bed-identity-ru.md).

Закрытие окна сохраняет приложение в трее. Полный выход — меню трея «Выход»
или Cmd+Q на macOS. Текущая сборка Windows ещё не проверена; подготовленная
спецификация не равна проверенному EXE.

Подробные результаты и ограничения: [отчёт](../development/user-candidate-report-2026-11-16.md).
